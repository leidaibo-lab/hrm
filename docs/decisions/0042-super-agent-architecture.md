# ADR-0042 采用 Super-agent 作为核心架构

> 状态：已接受 · 日期：2026-11-16 · 级别：L3

## 决定

本平台的智能能力采用 Super-agent 架构，不以单会话 Agent 为基本单位。

- **单实例、双层**：Router 常驻，负责人类交互、准入与分派，不执行具体任务；Worker 上下文隔离、并发执行、不直接对人说话，只向 Router 汇报。
- **事件驱动**：外部事件归一为不可变 Trigger；程序层做 Fast Path 过滤，模型层做 Slow Path 研判；已订阅 Thread 的后续事件直通 Worker，不经过 Router。
- **上下文连续**：Thread 是共享锚点，Correlation 只补上下文、不参与路由；上下文按 Inline & Spill 注入，并沿引用图做链式召回。**实例边界即上下文共享边界**：共享上下文的共用一个实例，需要隔离的各自配备。
- **状态外置**：业务状态存 PostgreSQL，Mastra 只存记忆与运行快照，不成为第二套真相源。
- **全双工交互**：前台不被后台任务阻塞，长任务在后台执行，完成后以事件回投。
- **外部 Watchdog**：独立定时回路判断 Worker 是否有实质进展，而不只探进程存活；实现优先采用 Mastra Schedules，不重复造调度器。
- **克制的主动**：只在必须由人决策或人能用上结果时出声；IM 单次回复保持简短。

Mastra 作为执行框架，承担 Agent、Workflow、Memory、Scorer、Tracing、Schedules 等能力；授权、审计、任务状态不属于 Mastra。

## 被否决的选项

- **单 Session + Subagent 工具**：分工依赖提示词与模型临场判断，实验中出现长尾，完成时间不稳定。
- **全事件溯源**：以事件回放推导业务状态，复杂度高；用只追加事实表加显式状态字段即可满足审计。
- **多实例共享同一上下文**：破坏权限边界，跨实例只能走 A2A 消息，不能共享记忆。
- **自建调度、恢复与记忆**：与“优先复用第三方实现”冲突，且维护成本高。
- **把 Watchdog 做成纯进程探活**：无法发现模型陷入无效循环或偏离目标。

## 后果与回滚

新增 `agentic`（编排）、`connector`（集成）与 `runtime`（执行）三块；`apps/api` 保持 HTTP 与 worker 两个入口，执行层嵌入 worker 进程。

PRD 引用本 ADR 说明取舍，不复制论证；具体范围与验收由 `docs/prd/agentic/` 承载。

回滚：停用 `agentic` 模块与 connector 注册、移除 worker 中的 runtime 装配；已写入的只追加表保留供审计，不再产生新记录。
