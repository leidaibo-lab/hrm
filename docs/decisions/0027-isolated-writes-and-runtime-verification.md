# ADR-0027 按修改意图写入与运行验收

> 状态：已接受（脚本模块模式被 0028 取代） · 日期：2026-11-08 · 级别：L3

## 决定

用户确认修复已审阅缺口：供应商和模型启停只更新 enabled，配置只写本次提交字段；未传凭据不轮换，未传模型字段不回写，显式 null 可清除默认参数。不恢复 version 或改变同字段以后提交为准的策略。以隔离数据库旧快照交错写入证明操作互不覆盖，完整应用迁移链并断言 version 列不存在。

保留本次工作期间外部删除 scripts/package.json 的修改，脚本入口改用 CommonJS 的 __dirname/__filename，与根项目模块模式保持一致，不再依赖额外 package.json。补充架构检查对路径别名、再导出、类型/动态导入及 Nest 导入别名的正反例；本次保护基线更新有明确任务授权，不削弱原规则。浏览器验收仅针对独立本地测试库；SDK 生成显式使用无扩展名导入，避免离线输入影响推断后生成 Turbopack 无法解析的 .js 路径；CI 继续无构建、无数据库和无服务。GitLab 仅核验可访问状态，不未经确认修改远端权限或推送工作区。

## 被否决的选项

- 保存整个聚合快照：名称或启停操作会覆盖其他修改。
- 恢复版本锁：不符合用户移除字段的明确决定。
- 用静态检查代替数据库与浏览器验证：无法证明实际交互与事务行为。

## 后果与回滚

端口按配置字段白名单与启停能力区分，调用方同步迁移；同字段的陈旧写覆盖风险仍明确保留。检查样例增加而非放宽。回滚必须同步端口、调用方及测试，临时库与验收服务仅用于本地测试，远端无法核验时如实列出缺口。
