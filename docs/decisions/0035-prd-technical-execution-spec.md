# ADR-0035 PRD 承载技术执行规格

> 状态：已接受 · 日期：2026-11-15 · 级别：L3

## 决定

允许演进型 PRD 同时承载产品需求和同一功能的技术执行规格。产品章节回答目标、场景、范围和验收；技术章节回答公共 API、接口、文件职责、迁移、验证、发布和回滚。章节必须分离，状态必须使用 `[已确认]`、`[待实现]`、`[延后]`。长期跨功能规则仍落在 `docs/conventions/*`，架构取舍落在 ADR；实现后 Nest DTO/OpenAPI 与源码成为对应事实来源。

## 被否决的选项

- 继续禁止 PRD 技术章节：会让执行 AI 在多个文档之间拼接上下文，增加方案漂移。
- 把所有 table-view 细节写入全局规范：会把单功能实现细节提升为全局约束，增加维护和冲突成本。
- 只写技术方案、不写产品章节：会丢失范围、交互和验收上下文。

## 后果与回滚

`docs/prd/_TEMPLATE.md` 增加技术执行和 AI 执行章节，文档检查器校验完整章节。`docs/prd/table-view.md` 成为 table-view 的交接主文档。回滚时删除本 ADR 和新增技术章节，恢复 PRD 只承载产品需求的治理条款，并恢复检查器基线。
