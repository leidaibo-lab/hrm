# ADR-0023 架构规范与防漂移闭环

> 状态：已接受（并发版本字段与 CI 执行范围被 0024 取代） · 日期：2026-11-08 · 级别：L3

## 决定

用户确认实施最终方案：规范约束实现、事实如实记录，替换 ADR-0020 中与此冲突的优先级；稳定规则 ID 不绑定章节位置。保留现有 docs 组织、具名 `<域>.module.ts`、domain 端口，不新增 ports 目录。API/Web 架构检查使用 AST 与真实公开面，检查必须有正反例。完成存量原子性、并发、缓存与表单整改；GitLab CI 文件进入仓库，服务器合并保护须另行核验。现行条款分别落在 governance、architecture、frontend、naming、persistence、testing 和 verification。

## 被否决的选项

- 依据现有实现自动改规范：会固化违规，失去约束作用。
- 新建 application/ports 或逐操作用例类：增加第二套位置，当前无需引入。
- 只依赖本地 hook 或规则映射绿灯：无法证明语义正确，也无法约束绕过本地 hook 的合并。
- index.module.ts：不提供默认目录解析，丢失文件业务身份。

## 后果

新增检查及其保护范围、稳定 ID、现行篇数上限校验是明确批准的检查设施变更；原有禁止项继续保留，只有文档位置绑定与恰好18篇的错误断言改为批准的稳定身份与上限语义。每项新约束以正反例和实际代码执行验证。代码、检查、规范和 CI 按依赖顺序可独立审阅，回滚不得只移除检查；数据库仅兼容性新增迁移，不改已应用迁移。未运行的 GitLab 管道与服务端设置不能声称已生效。
