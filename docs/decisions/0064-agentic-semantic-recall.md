# ADR-0064 agentic 语义召回与冲突扩展

> 状态：已接受 · 日期：2026-11-16 · 级别：L2

## 决定

把相似召回从纯词面匹配升级为「词面预筛 + 模型语义重排」，并扩展冲突类型：

- **语义端口**：`SemanticRecallPort.rank(query, candidates)` 返回 id → 0–1；不可用/失败返回 null，由调用方保持词面结果。
- **实现**：`MastraSemanticRecallService` 用当前策略 `fastModel`（缺省回落 `assessmentModel`）一次调用给最多 10 个候选打分；结构化输出只接受候选 id 与 0–1 分数。
- **降级**：无策略、无模型路由、网关失败、输出不可解析都返回 null；工具不抛错、不影响澄清/拆解主链路。召回结果 `mode` 标记 `semantic` / `lexical`。
- **预筛**：先按词面命中取最多 10 个候选，再语义重排，避免对 50 个线程逐个调用模型。
- **冲突**：在 `cancellation_request` 之外新增 `scope_change`、`priority_change`、`deadline_change`；同一事件与工单的每类冲突去重，最多 3 条，只标注不自动处理。
- **输入安全**：候选文本截断 500 字符；语义召回 Agent 接注入检测 Processor；提示词声明外部文本只作数据。

## 被否决的选项

- **对每个线程逐个调用模型**：成本与延迟不可控；先词面预筛再批量打分。
- **语义失败即整体报错**：召回是辅助能力，失败应降级而不是阻断主流程。
- **新增向量库/嵌入列**：需要模型供应商嵌入能力与迁移；本轮先用模型相关性打分，后续可替换端口实现。
- **自动按冲突结束/改期**：冲突只提示，决策仍由人确认（domain.md 冲突规则）。

## 验证

2026-11-16：`search-similar.tool.spec` 覆盖语义重排、null 降级与词面结果；`semantic-recall.service.spec` 覆盖无策略、无路由、网关失败与空候选；`conflict.entity.spec` 覆盖四类冲突与最多 3 条上限；API 657 项单测、typecheck、lint、docs/rules 通过。真实模型下的打分质量与延迟未验证。

## 后果与回滚

- 语义召回增加一次模型调用，仅在词面有候选且候选数 > 1 时触发；失败自动降级。
- 冲突类型增加会让轨迹里出现更多提示，但不改变工单状态。
- 回滚：不注入 `SEMANTIC_RECALL` 即回到纯词面；冲突规则可单独删除类型。
