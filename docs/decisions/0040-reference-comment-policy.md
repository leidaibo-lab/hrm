# 规则引用注释口径与机检语义对齐

> 状态：已接受 · 日期：2026-11-15 · 级别：L3

## 决定

全量审查治理执行（2026-11-15，用户确认「修复上述所有问题」）涉及三处检查设施变更，登记如下：

1. **CMT-4.4 机检语义**：`code-comments.md` 规则 13 明确「契约说明在场 + 括注编号并列」合规、引用作为注释主体违规。两处机检落点同步为同一语义：`scripts/checks/code-quality.ts`（AST 级，增量生效）与 `apps/api/src/__tests__/code-comments.spec.ts`（正则粗筛，全量源码），判定统一为「移除全部引用后正文 CJK 少于 4 字即违规」。正则粗筛无法区分字符串与注释，`quality-gates.spec.ts`（引用样例注册文件）在该项豁免，AST 级判定承接精确性。`quality-gates.spec` 增补括注并列合法样例与裸引用违规样例。
2. **架构白名单**：`architecture.spec.ts` 登记显式例外 `platform/http/outbound-policy.ts`（无状态策略文件，不套 `<cap>.service.ts` 命名），治理依据 ADR-0038。
3. **权限矩阵快照**：角色整体资料更新由 `PUT /roles/:id` 改为 `PATCH`（CON-5.2 口径），快照随契约变更重生成；前端 codegen 同步（ADR-0038 同批交付）。

被否决的选项：维持「任何引用即违规」（与规范「代替契约说明才违规」冲突，且会把 30+ 处既有括注溯源全部定为违规，需无意义大改）；仅扩 code-comments.spec 正则不动 canonical scanner（两落点语义漂移）。

## 后果

括注并列引用在增量与全量两个口径下行为一致；裸引用（分节注释仅挂编号）在文件被再次修改时由增量机检拦截。回滚为恢复三个文件的旧判定逻辑并重生成基线；快照回滚需同时恢复 PUT 路由，属契约回退，须另经决定。
