# 增量质量治理与规范职责补齐

> 状态：已接受 · 日期：2026-11-15 · 级别：L3

## 决定

用户已确认实施最终方案：新增 code-quality、database、security、runtime 四篇规范，现行文档预算由 19 调整为 23；保留单篇与任务阅读预算。数据库建模与完整性从 persistence 分离，既有规则 ID 保留。通用规则、业务规则、现状分别归 conventions、PRD、reference。

检查按开发工作区、实际暂存快照、CI merge-base 三种上下文执行；增加保存监听、验证计划、统一诊断、内容摘要和结果过期检测。增量入口不替代现有 hook/CI 全仓门禁。采用已有 Biome、TypeScript AST 和隔离测试，不增加依赖。代码与数据库行为不能由结构检查代替。

新编码约束适用于新增或内容修改的手写源码文件；存量未触及区域保留既有检查，并由 review 承接新规则。新增数据库模型或修改模型时执行数据库结构检查；未改模型不自动建立问题基线。检查脚本按工程职责检查，不将业务公共类型注释规则套到检查器内部数据结构。禁止自动生成豁免或接受历史违规。

允许更新本次实际修改的检查设施保护哈希；工作区原有保护文件变更必须在报告中另列，不以本 ADR 自动批准其内容。发布、线上门禁、真实数据库与恢复演练仍需对应环境证据。

## 被否决的选项

- 生成完整功能后才检查：反馈过迟，偏差持续累积。
- 增量检查替代全仓门禁：依赖分析可能遗漏消费方，降低现有保证。
- 大范围基线或目录豁免：掩盖存量问题和新增违规；本次不引入。
- 正则独自判断 TS/JSX 结构：无法可靠区分注释、字符串和语法；改用 AST。
- 所有规则声称自动覆盖：业务策略、数据库行为和人工验收仍必须显式报告。

## 后果

新规范可分别在写代码、建表、接入外部系统、调整运行行为时读取；每次任务仍按 index 路由读取。检查结果记录命令、退出状态、代码摘要、人工项和未验证项，源码变化使结果失效。

回滚按规范、检查器、调度、门禁四类独立撤销本次补丁并恢复对应哈希，不覆盖任务前已有改动；不执行数据库结构变更。真实数据库测试和远端保护未经核验时不得报告通过。
