# 0008: 前端与测试规范成篇、规则单源化与首批领域规范

> 状态：已接受 · 日期：2026-10-31 · 级别：L3

## 决定

1. 新增 `docs/conventions/frontend.md`：前端分层（自 `architecture.md`「前端基础」迁入）、组件划分、样式（Tailwind）、数据流转四节。
2. 新增 `docs/conventions/testing.md`：测试分层与 mock 纪律。
3. `architecture.md` 增补「数据层（Prisma）」节、「契约管线」7–9 条（路由资源命名、查询参数、错误码常量表）与「模块系统」规则 7（dto 命名）。
4. 规模预算与逐篇行数上限单源归 `governance.md`；`documentation.md` 更名「产出物写作规范」，适用范围扩大至 git 提交信息并并入提交规范节，删除与 governance 重复的强度词与预算表。
5. 默认值：组件文件 ≤ 400 行；className 行宽锚点 100 列（与 Biome `lineWidth` 一致）。调整需 ADR。
6. 新增机器验证命令（组件行数统计、className 长行检查）登记 `verification.md`。现行文档 10 → 12 篇。

## 被否决的选项

1. 前端与测试细则全部并入 `architecture.md`：估算约 122 行超出 120 行/篇上限；且全栈架构篇混入平台细则，路由价值下降。
2. 提交规范独立成篇：约 15 行不成篇，违背「入口轻、规则稳」的预算精神。
3. 推迟数据层、API 命名、测试规范至首个业务模块：无规范时首个模块会自由发挥并形成事实先例，事后矫正成本高于先立初版再校准；故本批落地为初版（规则 8 含初值标注），首个模块任务收口时校准偏差。

## 后果

- `index.md`、`AGENTS.md`、`governance.md` 的篇数与路由同步更新；结构检查断言 10 → 12。
- `architecture.md`「前端基础」收敛为指针。
- migrate 与 DB 集成测试命令保持「待落地」，随 docker 落地登记 `verification.md`。
- 领域词汇表与参考实现仍留待首个业务模块（前者无内容可写，后者属代码形态）；队列、日志细则等第三梯队不动。
