# ADR-0073 已关闭关注回答映射 409

> 状态：已接受 · 日期：2026-11-16 · 级别：L2

## 问题

闸门锁并发压测（同一 attention 20 并发回答）发现：只有 1 个请求成功，其余请求在拿到锁后发现关注已被关闭，抛出领域错误 `关注已关闭，不能回答`，最终返回 500。客户端无法区分“并发冲突/已处理”和“服务端故障”。

## 决定

`GateService.answerAttention` 在锁内执行回答时，把以下领域错误映射为 `ConflictException`（HTTP 409）：

- `关注已关闭，不能回答`
- `关注已过期，不能回答`

其他错误保持原样抛出，避免把真实故障伪装成冲突。锁获取失败原本已是 409，保持不变。

## 被否决的选项

- **在 controller 统一捕获字符串**：传输层不应理解领域文案；门禁编排层最接近错误来源。
- **返回 200 幂等成功**：同一关注被不同答案并发回答时，静默成功会掩盖答案冲突；409 让客户端重读状态。
- **新增错误类型**：领域层目前用 Error 文案表达状态违规，改类型会波及实体与测试；本轮只做边界映射。

## 验证

2026-11-16 本地隔离库 + 真实 API + Redis 锁：

- 20 并发回答同一 attention：**1×200 + 19×409**，关注最终 `answered`，无 5xx。
- 单测：回答已关闭关注抛出的错误在 `GateService` 映射为 409。
- 脚本：`scripts/ops/gate-lock-load.ts`，只允许 200/409，出现其他状态即失败。

未验证：多副本下锁 TTL 过期与网络分区；真实客户端重试策略。

## 后果与回滚

- 并发回答的客户端会收到 409，需要重读关注状态；不会重复推进闸门。
- 回滚：移除 catch 映射，恢复 500；不建议。
