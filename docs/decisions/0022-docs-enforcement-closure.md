# ADR-0022 文档可执行化：唯一源可机检、规则 ID 双向、检查独立化

> 状态：已接受（检查保护与覆盖状态部分被 0023 取代） · 日期：2026-11-06 · 级别：L3

## 决定

1. **唯一源可机检**：命令、计数、门禁、生成物路径、版本五类可变事实只保留一处定义（命令与门禁在 `reference/verification.md`，篇数预算在 `governance.md`「规模预算」），其余文档只写指针；`pnpm check:docs` 校验指针可解析、命令存在、版本与 `package.json` 一致。
2. **规则 ID 双向绑定**：格式 `<前缀>-<节>.<序>`——节号 = 文档中 `## ` 序号（从 1 计），序 = 该节内带 ID 条目按出现顺序（从 1 计）。机器可判定规则必须有 ID 并在 `verification.md`「规则 → 检查映射」登记落点；纯人工判定规则按篇登记，不强求 ID。ADR-0020 的旧扁平 ID（ARC-1 … DOC-2）一次性迁移为本格式并作废，历史提交中的旧 ID 不再解析。
3. **检查独立化**：人工 grep 全部脚本化到 `scripts/checks/` 并挂 `pre-commit`；`pre-push` 跑全量 `pnpm lint` 与 `pnpm test`；检查设施（五个横切 spec、`scripts/checks/`、`.husky/`、`biome.json`、`commitlint.config.ts`、`turbo.json`）一旦变动必须显式声明：`ALLOW_GATE_CHANGE=1` 提交并同步 `protected-files.json` 基线。
4. **ADR 是决策快照**，不作为现行规则校验对象；ADR 正文中的命令与命名以现行规范为准。据此，ADR-0011 的 commitlint 方案、ADR-0016 的文件名写法保持原文不动，由本决定声明其失效边界。
5. **阅读预算统一**：默认 ≤5 篇、新建带权限模块 ≤8 篇；skill 是执行顺序，其引用的文档计入预算。

## 被否决的选项

- **继续靠人工 review 与收口自证**：审计已证明失效——注册在册的 `: null` grep 实际 45 命中、其中 4 处真违规长期未修；「文档检查无脚本」的表述与已入库的 `docs-governance.spec.ts` 直接矛盾。
- **恢复远端 CI**：当前无远端仓库与多人协作，代价高于收益；`pre-push` + 保护基线是当前阶段的最小充分替代。出现远端与多人协作后再升级为 CI。
- **给全部 181 条规则条目编号**：纯人工判定条目（设计原则、注释摘要质量）加 ID 只增加维护成本，不产生检查能力，反而稀释「有 ID = 有落点」的信号。
- **把「18 篇」等计数彻底移出文档**：篇数预算是治理判据，必须保留一处可读定义，故保留在 `governance.md`「规模预算」，其余位置改指针。

## 后果

- 改一条命令 / 版本 / 篇数只需改一处，`pnpm check:docs` 拦截未同步副本。
- 新增规则必须先想清楚落点；想不清就不加 ID、按人工规则登记——**规则数量增长受检查能力约束**。
- 插入或重排 `##` 小节会使后续 ID 序号失效，`pnpm check:rules` 报错，必须同提交重编号并更新映射表（罕见但显式，属预期的漂移检测）。
- 保护基线不防「同提交改检查 + 改基线」的故意绕过；本决定只提高无意漂移与顺手放宽的成本，真正不可绕过仍依赖远端 CI。
- 规则 ID 变更会破坏历史提交中的引用，检索旧规则改用 `git log -S`。
