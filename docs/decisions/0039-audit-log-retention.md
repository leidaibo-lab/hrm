# 审计日志保留策略

> 状态：已接受 · 日期：2026-11-15 · 级别：L3

## 决定

`audit_logs` 为只追加事实表（主体、对象、动作、结果、traceId，见 `pipeline/audit/`），保留 **180 天**，到期后清理。首版采用人工周期清理（按 `createdAt` 分批 DELETE，经迁移评审的 SQL 或 psql 会话执行，单批 ≤ 10 万行并核对删除总量）；未引入定时任务与分区表。表已有 `createdAt` 索引支撑该清理路径；清理必须避开业务高峰并记录执行证据。

被否决的选项：无保留上限（审计表无界增长拖慢索引与备份）；立即引入 pg_partman / 定时任务（当前审计量小，重型机制违反 runtime「禁止无依据引入重型机制」）；软删或归档表（审计为只追加事实，纠正以新事实追加，不需要删除语义）。

## 后果

runtime「日志 3」的保留项由本 ADR 登记；`audit_logs` 模型职责说明与保留策略一致。审计量进入常规规模（如登录/管理动作显著放量）时，应先立 ADR 再引入定时清理任务或原生分区。回滚为删除本策略并恢复无上限保留，不影响存量数据；已按本策略清理的数据不可恢复——清理执行前必须确认备份窗口覆盖待删区间。
