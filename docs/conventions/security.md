# 安全与隐私基线

> 层：规范 · 时态：约束未来 · 失效：信任边界或安全决定变更时

## 目的

统一输入、外部系统和敏感数据保护；会话与授权的唯一规则在 authorization.md。

## 何时读取

处理凭据、敏感字段、外部地址、上传导出、身份边界或生产配置时。

## 适用范围

API、Web、任务、日志、数据库和交付配置；本篇按人工审查与行为测试执行，不声称已具备漏洞扫描或泄露检测门禁。

## 信任边界

1. 外部输入必须经运行时校验；禁止信任客户端传入的身份、权限或归属字段；资源范围必须进入应用服务及读写条件。
2. 用户可配置外部地址时，必须明确协议、目标网段、DNS/重定向和内网访问策略；不能只检查 URL 格式。
3. Cookie、来源检查与 CORS 必须按会话和部署边界配置；禁止把隐藏菜单或跨域策略当作授权。

## 敏感数据

1. 密钥、令牌、密码和完整凭据禁止进入代码、日志、审计明细或公开响应；密码必须不可逆哈希，需要恢复使用的密钥必须受控加密。
2. 响应必须字段白名单，日志必须脱敏；错误栈只进入受控诊断，禁止向用户泄露连接串或内部凭据。
3. 每类敏感数据必须明确访问方、保留与删除要求；备份和导出必须延续相同保护。
4. 密钥必须具备轮换、撤销和恢复方案；测试必须使用占位或专用凭据，禁止读取真实生产密钥。

## 资源与依赖

1. 请求体、上传、批量、导出与并发必须有边界，超限应给稳定错误；禁止无界缓冲或无限任务。
2. 运行账号与迁移账号必须按实际权限分离；破坏性操作遵守 ../process/boundaries.md。
3. 新增或升级依赖必须评审来源、运行权限和已知漏洞；扫描能力、漏洞处置责任和未解决风险必须如实登记，不得伪报扫描通过。

## 验证方式

- 人工沿输入→授权→查询/写入→响应→日志追踪信任边界，核对配置、脱敏及资源限制。
- 对越权、恶意外部地址、超限和凭据泄露风险补行为用例；真实外部访问不得进入普通测试。
- 运行与恢复要求见 runtime.md，验证命令和未落地能力见 ../reference/verification.md。
