# 测试规范

> 层：规范 · 时态：约束未来 · 失效：治理决定变更或测试基建变化时

## 目的

定各层测什么、怎么 mock、测试放哪里。避免低价值测试、过度 mock 与永不执行的测试。

## 何时读取

写或改任何 `*.spec.ts` / `*.spec.tsx` / `*.test.tsx`、评审测试 diff 时。

## 适用范围

`apps/`、`packages/` 全部测试。

## 放置与命名

1. 单测就近放同目录 `__tests__/` 子目录，文件名与被测对象一致并保留 `.spec.ts` 后缀；禁止顶层镜像测试目录。 `TST-4.1`
2. 跨切面测试（架构、路由、端点审计、注释检查、文档治理）放 `apps/api/src/__tests__/`，这是顶层测试目录的唯一用途。
3. 替身集中放 `__tests__/fixtures/` 或同目录 `fixtures/`，文件名 `*.fixture.ts`。
4. `apps/web` 的测试必须落在 vitest `include` 覆盖范围内（`lib/`、`features/`、`app/`、`components/`）；新增测试目录必须同步 `apps/web/vitest.config.mts`，否则测试不会执行。

## 分层与职责

1. **domain**：实体与值对象单测为主，断言行为与不变量，不 mock 内部方法。
2. **application**：依赖的 repository / 下游 service 用测试替身，断言行为与状态变化，不断言 mock 调用序列本身。
3. **controller / guard / 管道**：保持薄、逻辑下沉 service；正确性以最小集成测试覆盖（HTTP 或 Nest 测试模块），不为覆盖率凑单测。
4. **契约**：以 OpenAPI 为事实源，web 侧不手写接口类型断言；zod schema 的边界用例（必填缺失、超长、跨类型）必须覆盖。
5. **web 组件**：测用户可见行为（渲染结果、交互回调），禁止断言内部实现。

## mock 纪律

6. 禁止 mock 被测对象自身或其内部私有方法；替身只打在架构边界（适配器、外部 service、网络）。 `TST-6.1`
7. 替身集中维护（同目录 `fixtures/` 或 test utils），禁止每个用例内联手搓。
8. 快照仅用于纯展示产物；快照失败必须改写为显式断言，禁止盲更新。

## 数据库与外部依赖

9. DB 集成测试使用专用 TEST_DATABASE_URL、独立临时 schema，测试前应用迁移、结束清理；禁止使用业务 schema 或真实凭据。未提供测试数据库时必须报告未验证，不能算通过。
10. 测试禁止访问真实外部系统（无网络、无真实第三方凭据）。

## 验证方式

- `pnpm test` 全量通过（shared / api / web 三包；命令见 `../reference/verification.md`）。
- 覆盖率不设硬门槛，防止为凑数写低价值测试。
- 新增测试文件必须被对应包 `include` 命中：对应包的测试命令（见 `../reference/verification.md`「命令注册表」）会打印实际收集的文件数。

## 架构与运行环境

1. 新增机器约束必须有合法与违规样例，覆盖相对路径、alias、再导出、类型导入和可解析动态导入；未知动态目标必须报告。
2. 测试入口必须在导入业务前注入专用占位配置，不能依赖开发者真实密钥；生产环境校验不得放宽。
3. 结构检查不证明事务、权限、缓存和草稿语义；这些必须由行为测试及明确人工验收覆盖。
4. CI 只运行无外部服务的单元与架构测试，禁止构建、数据库、Redis、迁移或启动 API；DB 集成测试保留为按需本地验证，未执行必须单列。
