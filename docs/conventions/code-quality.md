# 通用编码质量

> 层：规范 · 时态：约束未来 · 失效：语言语义或检查能力变更时

## 目的

统一 TypeScript 的表达语义与边界行为；命名见 naming.md，注释见 code-comments.md，JSX 见 frontend.md。

## 何时读取

新增或修改手写 TS/TSX 逻辑、类型或异步操作时。

## 适用范围

apps、packages 的手写源码；生成代码、vendor 和测试样例不适用业务风格规则。新增机器规则按修改文件执行，未触及存量继续受既有门禁约束；禁止建立隐式基线。

## 类型与输入输出

1. 局部值应该由 TypeScript 推导；跨模块函数必须明确返回契约，外部未知数据必须以 unknown 接收并校验。自家 OpenAPI codegen SDK 的响应属契约内数据：校验外壳汇总字段（items 为数组、total 为非负安全整数等）即可，元素信任契约——契约侧由 api 出站 parse 白名单保证。禁止用 any、非空断言或双重断言掩盖错误；机器拦截非空断言，其余按类型检查与 review。类型适配确需断言时必须收敛为具名转换入口并注释失配依据与运行时安全前提。 `QLT-4.1`
2. 对象和数组输入可以声明 readonly；公共函数禁止隐式修改调用方数据，确需修改必须在契约说明。多个同类型位置参数应该改成具名对象。
3. 状态互斥时应该使用判别联合；禁止通过类型断言制造未满足校验的业务对象。

## 空值与布尔

1. 类型声明默认用 `?: T` 表达无值；业务上“不存在”同样用 undefined，不再用 null 表示。空集合返回空数组，禁止用空串、零或特殊日期冒充空值。 `QLT-4.2`
2. null 仅允许三类例外：出站序列化要求键存在且值为 null；持久化实体/快照与外部系统原样 NULL；入参需区分“省略”与“主动清空”且已 JSDoc 说明。其余位置出现 null 即违规。
3. 出站序列化省略无值键，不发送 null；目标协议不允许省略键时，在出站适配层把 undefined 映射为 null，业务层保持 undefined。
4. 迁移期例外只约束新增与修改代码：存量清单、责任、期限与退出条件统一登记在 ADR-0055，清单清零即删除本例外。
5. 默认值必须按语义选择：仅空值回退用 ??；合法的 0、false 和空串不得被 || 丢弃。安全访问可空对象应该用可选链。
6. 判空优先布尔：仅当类型不含空串、0、false 等合法 falsey 值，或已由 JSDoc 声明非空不变量时用 `if (x)`；否则用 `!= null`（同时覆盖 null 与 undefined）。仅在类型可证明不含 undefined 时允许严格比较。boolean 直接判断，需要转换时用 !!；数组内容判断用 length > 0，禁止把 !![]、!!{} 当作内容非空。
7. 更新时间字段必须区分省略、不修改、设置新值与主动清空；禁止以 truthiness 合并这些状态。

## 控制流

1. 禁止嵌套三元；多分支使用 if、提前返回或 switch。 `QLT-5.1`
2. 简单二选一可以用三元；包含业务副作用的分支必须使用 if，禁止用 &&/|| 隐藏保存、删除等操作。
3. 复杂条件应该使用有业务意义的变量；拆函数依据独立职责，禁止为规避行数限制压缩或机械拆分。

## 异步与错误

1. Promise 必须等待、返回或明确处理失败；void 不等于处理拒绝，禁止空 catch 吞错。机器检查空 catch，拒绝处理和错误转换由 review 与行为测试承接。 `QLT-6.1`
2. 独立任务可以并行；存在依赖的操作必须顺序执行。不得以成功空数据代替失败。
3. 超时、重试、取消与并发的运行要求见 runtime.md；错误契约见 contracts.md。

## 验证方式

- scripts/checks/code-quality.ts：AST 检查语法错误、非空断言、嵌套三元和空 catch；合法、违规样例见 `apps/api/src/__tests__/quality-gates.spec.ts`。
- 未自动覆盖的类型安全、空值语义、副作用、输入可变性和 Promise 责任必须人工检查；机器成功不代表这些条款通过。
- 命令及适用范围见 ../reference/verification.md。
