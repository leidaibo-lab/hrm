# 代码注释规范（JSDoc）

> 层：规范 · 时态：约束未来 · 失效：JSDoc 规则变更或 lint 工具承接时

## 目的

让注释承载契约与意图，而不是复述代码。公共 API 的调用约束必须能脱离实现被读懂。

## 何时读取

- 新增或修改 `.ts` / `.tsx` 导出符号时。
- 评审 diff 中出现 `/** */`、注释掉的代码或无主 `TODO` 时。

## 适用范围与不适用

- 适用：`apps/`、`packages/` 下所有 `.ts` / `.tsx` 源文件。
- 豁免：`apps/web/components/ui/`、`apps/web/components/ai-elements/`（vendor 组件库基座，随上游升级，不改写其注释）。
- 不适用：测试用例标题（用 `it(...)` 表达）、配置文件、构建产物；`docs/` 写作规范见 `documentation.md`。

## 规则

### 必须写与可以省略

1. **必须**为所有 `export` 的 function / class / interface / type / const 写 JSDoc 块注释。 `CMT-4.1`
2. 内部函数满足任一条件时**必须**写：参数 ≥ 3；有副作用（I/O、写状态、抛错）；边界条件无法从签名看出。
3. **可以**省略：一行映射、getter / setter、类型已完整表达且行为显然的常量（含 UPPER_SNAKE 标量常量）；行为由框架约定直接可见的入口符号（Nest controller 与模块类、Next 页面 / 布局 / 错误页组件、`dynamic` / `metadata` / `revalidate` 等框架配置导出）；由 schema 或常量直接推导、无额外语义的类型别名（`z.infer`、`Pick` / `Omit` / `ReturnType` 等）；zod schema 常量（形状即契约）。

### 格式

4. 公共 API **必须**用 `/** ... */` 块注释；**禁止**用 `//` 或 `/* ... */` 代替。
5. 短摘要**可以**使用单行 JSDoc；多行 JSDoc 的中间行**必须**以 `*` 开头。
6. 标签**必须**独占一行，格式为 `@tag 值`。

### 内容

7. 首行摘要**必须**简练：单句、不超过 60 个字符，陈述契约（做什么、返回什么），以句号结尾。
8. 摘要**必须**单句；**可以**另起至多 2 行补充非显然约束；**禁止**展开背景或教程。`@param` / `@returns` 各为单句。
9. **禁止**用注释复述代码、记录作者 / 日期 / 改动历史；这些由 git 承接。
10. **禁止**保留注释掉的代码。 `CMT-4.2`
11. `TODO` **必须**带负责人或 issue 编号，否则**禁止**提交。 `CMT-4.3`
12. 描述**必须**使用中文；标签、标识符、类型名保留英文原文。
13. 注释正文**禁止**用本地文档路径、PRD/ADR 编号或规则编号代替契约说明；编号类引用只能以括注形式并列在契约说明之后（如「……一律 400（contracts.md 路由与查询 4）」），不得成为注释主体；无增量溯源必须移至 ADR 或提交信息。 `CMT-4.4`

### 标签

14. 参数有签名之外的信息（约束、单位、缺省语义、边界）时**必须**写 `@param 参数名 - 单句含义与约束`；写不出增量时**可以**省略，**禁止**复述签名。
15. TS 签名已表达类型，**禁止**在 JSDoc 中重复 `{类型}`。
16. 有返回值**必须**写 `@returns`；返回 `void` 或语义已由摘要表达时**可以**省略。
17. 公开函数会抛错时**必须**写 `@throws`，写明触发条件。
18. 标记 `@deprecated` 时**必须**给出替代项或迁移方向。
19. 调用方式非显而易见时**可以**写 `@example`；关联契约**可以**写 `@see`。

### 一致性

20. JSDoc 与 TS 签名**禁止**矛盾；冲突时以签名为事实源并修 JSDoc。
21. 注释只写契约与为什么，**禁止**写使用教程；教程进 `docs/`。
22. 摘要**必须**提供签名与装饰器之外的增量信息（约束、副作用、非显然边界）；复述路由语义、权限点或参数类型的注释视为违规。判定动作：删掉该注释后读者是否损失信息。

23. 新增或修改的导出对象 type/interface **必须**为每个自行声明的字段/方法写 JSDoc；嵌套对象同样适用；继承/映射/推导类型不重复已有说明。内部简单类型**可以**不写，存在非显然约束时必须统一说明。 `CMT-4.5`
24. 字段摘要必须说明业务角色，非显然默认值、单位、可空语义和调用时机必须补充；禁止只翻译 TS 类型。自动检查只保证覆盖，自包含与语义由 review 承接。

## 附录：对照示例

```ts
// 坏：复述装饰器，删掉后零信息损失
/** 用户管理（平台后台）：user:manage 权限点。 */
@Controller('users')
export class UserController {}

// 好：写装饰器之外的行为约定
/**
 * 全量替换角色的权限点授予关系；保存即影响下一请求的 API 拦截。
 * @param permissionCodes - 目标权限点全集；含未知或已废弃项时按未知处理。
 * @throws 角色不存在 404；内置角色 409。
 */
async setPermissionPoints(id: string, permissionCodes: string[]) {}
```

## 验证方式

- `apps/api/src/__tests__/code-comments.spec.ts` 机器检查：`export` 缺 JSDoc、注释以文档路径/规则编号/ADR 编号为主体（移除引用后正文近乎为空）、注释掉的代码、无归属 `TODO`；「契约说明 + 括注编号」并列形式的语义厚度由 review 承接。
- 摘要质量、增量信息与标签准确性由 code review 承接（规则 7 / 8 / 22）。
- 依据 ADR-0002，本规范曾整体不设验证项；2026-11 起对可机器判定的四类恢复机检（见 ADR-0020）。
