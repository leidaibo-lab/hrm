## 二、产品定位与价值

agentic 是常驻的 Super-agent 任务托管平台：一个调度内核，把外部事件授权成任务，由 AI 执行、由人决策，全过程可回放。它不绑定具体业务场景，业务通过 Source 插件接入、能力通过 AgentSpec 与 Policy 接入。

平台价值在于把会话管理、上下文同步与任务调度从人手里移到系统层：人多任务并行不再受注意力限制，业务接入不再改内核。

四条设计约束：连续（跨会话共享同一件事的上下文）、高效（多任务并行互不阻塞）、主动（按规则推进，不等人 @）、持久（常驻、异常自恢复）。

## 三、背景与问题

- 现有 Agent 与单次会话绑定：每多一项任务就新建对话、补背景，人仍然是调度员。
- 多任务上限取决于人的注意力，不是模型能力。
- 会话状态不可恢复：进程重启、上下文丢失，任务无法续跑。
- 外部系统接入各自为政：每接一个系统都要改核心，无法复用调度、授权、审计与恢复。
- 缺少统一的授权、幂等、外部副作用与人工介入机制，无法安全地托管真实工作。

## 五、范围与非目标

本期范围：Super-agent 平台内核——Engine（调度、研判、工单、派工）、Scheduler（队列与准入）、Runtime（Mastra 执行宿主）、Sources（飞书）、Spaces（空间可见性）、Workspace/Sandbox、Effects/Outbox、Passes/Watchdog、模型网关、控制台与审计。

非目标：

- 不接入具体业务场景，业务能力由后续 AgentSpec 接入；
- 不做多租户与组织部门；单组织部署，Space 是数据可见性边界；
- 不做知识库与文档级授权；
- 不做代码执行（建分支、改代码、提 MR）、MCP、Skills、跨实例 A2A；
- 不做多副本运行租约与写栅栏（V0 单实例）；
- 不做业务定制面板与报表，控制台只保留平台运维视图。

## 七、一页架构

```
外部系统（飞书）
   │ 长连接事件 / 卡片动作
   ▼
Sources（插件）── Trigger ──▶ Engine（唯一写者）
                                ├─ Intake：硬过滤、Gate、线程、订阅直通
                                ├─ Evals：Assessment → Decision
                                ├─ Tickets：工单、授权、关注
                                └─ Assignments：调度、投递、回报、恢复
Scheduler：全局队列、优先级、公平、互斥、租约、背压
Runtime：Mastra 持久执行 + Workspace/Sandbox + 工具
Evidence：TraceSink + Outbox + 审计
外部依赖（独立 PRD）：model-gateway、iam
Panel：只展示需要人的、系统健康的、历史
```

五条要点（详见 [design.md](design.md) 第二节）：

1. 双层职责：Engine 常驻负责准入与分派；Worker 上下文隔离、并发执行，只向 Engine 汇报。
2. 事件驱动与三级过滤：硬过滤、Gate、订阅直通内联完成；只有需要模型的慢路径入队。
3. 异步多信道：飞书 Source 自带 Channel；前台不被后台任务阻塞，结果以事件回投。
4. 存算分离：业务状态只在 PostgreSQL；Mastra 记忆与快照只作可重放缓存。
5. 持久可恢复：durable 会话、幂等工具、外部写账本，崩溃后继续且不重复外部写。

技术栈：NestJS + zod（API）、BullMQ（队列/效果）、PostgreSQL + Prisma（事实源）、Redis（队列/锁/限流）、Mastra（Agent 运行时）、Next.js（控制台）。

## 八、非功能需求与成功指标

### 8.1 平台目标

| 目标         | 成功指标                                                   | 目标值           |
| ------------ | ---------------------------------------------------------- | ---------------- |
| 主链路可跑通 | Source→Trigger→Eval→Ticket→Assignment→Report→Outbox 端到端 | 一条链路通过     |
| 可插拔       | 新增 Source / AgentSpec 是否需要改内核                     | 核心零改动       |
| 隔离         | 会话/工作区按工单隔离；跨 Space 越权                       | 0 例             |
| 恢复         | 宿主重启后未完成执行继续，外部写重复                       | 继续且 0 重复    |
| 可追溯       | 运行审计覆盖率；按 traceId 回放                            | 100% 可回放      |
| 性能         | 事件到首次派工 / 面板列表                                  | P95 ≤ 60s / ≤ 1s |
| 成本         | 单次执行可观测，异常可告警                                 | 成本可归集       |

### 8.2 非功能需求

| 类别   | 要求                       | 可判定指标                      |
| ------ | -------------------------- | ------------------------------- |
| 安全   | 权限最小化、密钥不进上下文 | 越权用例 0 通过；日志无明文密钥 |
| 可用性 | 单实例可恢复               | 重启后状态不丢、执行可继续      |
| 可观测 | 审计、指标、健康、告警     | 运行与外部写可追溯              |
| 兼容性 | 平台基线版本               | Nest/Next/Prisma 与仓库基线一致 |
