## 二、产品规格（A）

### A1 功能目标与非目标

| 类型   | 内容                                                                                                                                                                                                     |
| ------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 目标   | 关注是一等公民：每条关注必须有等待对象与时限，缺一不可创建，不允许「无人承接的问题」                                                                                                                     |
| 目标   | 两段式人机等待：关注是等待状态的唯一事实源，会话侧挂起只承载等待；人可在飞书卡片与 Web 两个入口做确认、修改、驳回；回答结构化保存，不推断自由文本                                                        |
| 目标   | 超时只升级、不自动通过：关注 72 小时、升级与停滞复查 24 小时、提醒窗口 12 小时；同一工单的闸门串行；到期前提醒、到期后升级、停滞时补关注三类扫描兜底                                                     |
| 非目标 | 不定义问题内容与执行质量（见 03）、不定义工单状态机（见 03）；不做自动审批或代答、不做跨工单批量决定、不做通知渠道治理与卡片样式规范、不引入关系型资源授权（只保留空间成员判定）；本期不接入具体业务场景 |

### A2 角色与入口

| 角色       | 可观察行为                                                                                     |
| ---------- | ---------------------------------------------------------------------------------------------- |
| 请求人     | 作为授权发起人，缺省成为等待对象；收到指向自己的问题，可在任一入口回答；回答后关注从其待办消失 |
| 空间负责人 | 被升级或被停滞关注指向；可查看本空间内全部待办                                                 |
| 平台管理员 | 不受空间限制，可查看全部待办                                                                   |
| Engine     | 在派工、停滞、运行失败、出站永久失败等节点发起关注；关注状态的唯一写者                         |
| Executor   | 经内部回报上报运行失败，由 Engine 转为关注                                                     |
| Source     | 经 Channel 回投出站永久失败，由 Engine 转为关注                                                |

入口：飞书卡片（确认/修改/驳回）、Web 待办页与工单详情待办区；两个入口回答同一份结构化问题，结果一致。

### A3 功能逻辑与判定

#### A3.1 创建与必填

| 要素     | 规则                                                         |
| -------- | ------------------------------------------------------------ |
| 问题     | 非空文本；类型为确认、补充、评审、审批之一                   |
| 等待对象 | 显式指定优先；缺省回落工单授权发起人；两者皆空 → 拒绝创建    |
| 时限     | 显式指定优先；缺省为创建时间 + 72 小时                       |
| 初始状态 | 待答；创建本身不产生外部副作用，卡片与提醒在提交后经出站投递 |

- 失败分支：问题为空、等待对象为空、时限非法 → 拒绝创建并报错，不得以「稍后补人」的方式保存。

#### A3.2 两段式等待

| 段   | 动作                                                                                      | 约束                                           |
| ---- | ----------------------------------------------------------------------------------------- | ---------------------------------------------- |
| 事实 | 创建事务只写关注（待答、截止时间、等待对象）并写审计                                      | 关注是等待状态的唯一事实源                     |
| 挂起 | 会话侧以挂起承载等待，记录关注标识、问题、选项与恢复标签                                  | 挂起不是事实源；挂起丢失时可按关注重建         |
| 回答 | 人在任一入口回答；事务内关注待答 → 已回答（条件更新，重复回答按冲突处理），提交后恢复会话 | 回答、决定人、决定时间与答案为结构化事实       |
| 超时 | 扫描命中截止时间 → 已过期 → 生成 24 小时复查关注 → 取消等待中的运行                       | 超时不自动通过、不写答案                       |
| 串行 | 同一工单同一时刻只受理一条回答并推进                                                      | 由关注唯一约束与工单锁保证，不依赖会话挂起机制 |

- 失败分支：会话已不存在 → 只更新关注并提示已处理；恢复会话失败 → 记录并重试，不把关注回退为待答；重复回答返回冲突。

#### A3.3 回答与三类决定

| 决定 | 语义                   | 后续影响                                       |
| ---- | ---------------------- | ---------------------------------------------- |
| 确认 | 接受当前编排稿作为依据 | 本关注关闭；本工单无其他未答问题时推进下一步   |
| 修改 | 按回答内容修订后接受   | 追加修订版本并关闭关注；基于旧稿的产物版本失效 |
| 驳回 | 拒绝当前方向并给出原因 | 关闭关注并结束工单，原因取回答或驳回原因       |

- 回答必须带非空答案；驳回可附原因（≤500 字）。回答后状态为已回答，记录回答者与回答时间。
- 同一工单仍有未答关注时，不推进下一步；全部答完才进入后续处理。
- 失败分支：重复回答、关注已过期、关注已关闭 → 返回冲突并提示已处理；答案为空 → 拒绝。

#### A3.4 同一工单串行

- 同一工单同一时刻只受理一条回答并推进下一步；其余请求被拒并提示稍后重试，任何入口都不得出现两次推进。
- 推进过程中若发现关注已被回答、已关闭或已过期，统一按冲突处理，不表现为系统故障。
- 失败分支：受理入口不可用时放行并告警，随后由关注状态校验兜底；重复请求不得产生第二次推进。

#### A3.5 超时与升级

| 场景             | 处理                                                                                                 |
| ---------------- | ---------------------------------------------------------------------------------------------------- |
| 关注到期未答     | 标记为已过期；不自动通过、不自动采纳默认选项                                                         |
| 非复查类关注过期 | 生成一条复查关注给策略负责人（按来源类型覆盖，缺失回落授权发起人），时限 24 小时，并取消等待中的运行 |
| 复查类关注过期   | 只提醒等待对象，不再生成新的升级关注，避免无限链式升级                                               |
| 升级对象缺失     | 记录告警，不生成无人承接的升级关注；原关注保持已过期                                                 |

- 失败分支：负责人缺失 → 回落授权发起人；两者均缺失 → 不创建升级关注并告警，原关注保持已过期；过期处理失败 → 下一轮扫描重试。

#### A3.6 提醒与扫描

| 扫描       | 触发与范围                                           | 行为                                     |
| ---------- | ---------------------------------------------------- | ---------------------------------------- |
| 到期前提醒 | 待答关注进入截止前 12 小时窗口                       | 提醒等待对象；同一条关注只提醒一次       |
| 过期扫描   | 周期扫描全部待答关注，命中截止时间                   | 转已过期并按 A3.5 升级或提醒             |
| 停滞扫描   | 进行中工单超过 24 小时无进展、无待答关注、无活跃执行 | 生成复查关注给负责人，时限 24 小时       |
| 扫描开关   | 策略可关闭停滞扫描                                   | 关闭时跳过停滞扫描，到期与提醒扫描仍执行 |

- 失败分支：扫描异常 → 记录并等待下一轮，不中断其他扫描；同一关注不重复提醒；提醒发送失败按通知重试规则处理。

#### A3.7 入口与可见性

- 飞书卡片：展示问题、选项、等待对象与截止时间，提供确认/修改/驳回三个动作；卡片动作回到系统后按 A3.3 处理。
- Web 待办页：按类型筛选待答关注；逾期显示醒目标记；输入回答后选择确认/修改/驳回；回答成功即从列表移除。
- 工单详情：显示该工单未关闭关注与等待对象，可跳转处理。
- 可见性：待办列表按工单所属空间的成员关系过滤；越界关注按不存在处理，回答同样拒绝。
- 失败分支：卡片动作重复提交 → 冲突提示；Web 回答失败 → 展示错误并保留输入；越权访问 → 按不存在处理。

### A4 状态与数据流转

| 状态     | 进入方式 | 可执行动作                                   |
| -------- | -------- | -------------------------------------------- |
| open     | 创建关注 | 回答；到期后转过期；被提醒                   |
| answered | 人回答   | 只读；保留答案、决定人、决定时间             |
| expired  | 到期扫描 | 只读；非复查类可派生新的复查关注，并取消运行 |

```
派工/执行/停滞/失败 ─▶ 创建关注（等待对象 + 时限）─▶ 会话挂起（只承载等待）
        ├─ 回答 ─▶ answered ─▶ 未答问题清零 → 恢复会话并推进下一步；否则继续等待
        └─ 到期 ─▶ expired ─▶ 非复查类：生成复查关注（24h）并取消运行；复查类：只提醒不升级
```

不变量：I9 关注必须有人、有时限；超时升级而非自动通过；同一工单闸门串行；重复回答不产生第二次推进。

### A5 交互与异常

| 场景     | 可观察行为                                                           |
| -------- | -------------------------------------------------------------------- |
| 待办列表 | 按类型（全部/确认/补充/评审/审批）筛选；显示工单、等待对象与截止时间 |
| 逾期标记 | 已过截止时间的关注显示逾期标记并排在醒目位置                         |
| 回答操作 | 输入非空答案后可提交；确认/修改/驳回三键互斥，提交中禁用             |
| 回答成功 | 关注从待办移除；工单详情同步更新；推进结果在轨迹中可见               |
| 卡片入口 | 卡片展示同一问题与选项；动作结果与 Web 一致，重复动作给出已处理提示  |

异常：关注不存在或不可见 → 按不存在提示；已被他人回答或已过期 → 冲突提示并刷新；答案为空 → 提示补充；通知发送失败 → 保留待办并重试，不静默丢失；并发回答 → 仅一次成功，其余为冲突。

### A6 扩展与接入点

**数据接入点**

- 派工与执行结果：把待确认问题转为关注，等待对象取事件发起人或策略负责人。
- 执行与出站失败：运行失败转复查关注；出站永久失败转复查关注。
- 停滞扫描：按工单无进展条件补发关注。
- 人的回答：卡片与 Web 两个入口，回答内容结构化保存后恢复会话继续推进。

**扩展点**：关注类型（新增类型须声明是否参与升级链）；通知渠道（新增入口只做展示与回答，不改闸门判定）；升级策略（负责人按来源覆盖，可在策略中扩展）；提醒窗口与升级时限（按策略扩展，缺省 12h/24h/72h）。**接入约束与禁止项**：禁止创建无等待对象或无时限的关注；禁止用自由文本推断「等待人」；禁止超时自动通过或自动采纳默认答案；禁止绕过串行受理并发推进同一工单；禁止在回答前产生外部写；禁止把关注当工单结束手段（驳回结束工单仍按 03 的规则执行）；禁止把会话挂起当作等待事实源。

## 三、技术设计（B）

### B1 模块与文件

模块总目录、分层依赖与命名以 [design.md](design.md) 第六节为准；本域只列归属 04 的子树与入口，路径相对 `apps/api/src/modules/agentic/`。

| 区域     | 路径                                                                                                          | 职责                                                       |
| -------- | ------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------- |
| 入口     | `attention.controller.ts`、`dto/`                                                                             | 待办列表与回答端点；zod 校验                               |
| 领域     | `domain/attention/`、`domain/port/`                                                                           | Attention 聚合、状态错误与升级规则；仓储、送达与锁端口     |
| 应用     | `application/engine/tickets/`、`application/notices/`、`application/passes/`、`application/runtime/`          | 关注创建/回答/过期与闸门串行；送达会话；周期扫描；执行装配 |
| 出站     | `application/outbox/`、`infrastructure/channels/`、`infrastructure/sources/lark/`                             | 提醒与升级经 Outbox 由 Lark Channel 发送                   |
| 持久化   | `infrastructure/persistence/`                                                                                 | Prisma Store 实现关注与工单端口                            |
| Web/共享 | `apps/web/app/(workspace)/attention/`、`apps/web/features/agentic/attention/`、`packages/shared/src/agentic/` | 待办页与切片、枚举与队列名                                 |

- Engine 是唯一写者：关注状态只由 Engine 写入；会话侧只承载等待，不写库（design.md 2.4、2.5、4.4）。

### B2 数据表

本域归属 `agentic_attentions` 一张表；全量表清单与归属见 [design.md](design.md) 7.2，字段级定义以 Prisma schema 为准。

| 表                   | 关键字段                                                                                                 | 约束与索引                                                                           | 保留            |
| -------------------- | -------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------ | --------------- |
| `agentic_attentions` | id、spaceId、ticketId、kind、question、options、status、assignee、deadline、decidedBy、decidedAt、answer | assignee/deadline 非空；`(status,deadline)`、`(ticketId,status)`、`(spaceId,status)` | 关闭后保留 1 年 |

- 状态 open/answered/expired；类型 confirm/clarify/review/approval（确认/补充/评审/审批）；只更新决定相关列（status、decidedBy、decidedAt、answer），不删除历史关注。
- 会话挂起记录属运行时快照（工作流快照），只用于恢复等待，不是业务事实源；快照丢失时按关注重建等待。

### B3 接口与队列

| 方法与路径                           | 权限                       | 行为与失败分支                                                                    |
| ------------------------------------ | -------------------------- | --------------------------------------------------------------------------------- |
| `GET /agentic/attention`             | `agentic.ticket:read`      | 列出待答关注，可按 kind 过滤；逐条按工单所属空间的成员关系过滤；最多返回 50 条    |
| `POST /agentic/attention/:id/answer` | `agentic.attention:update` | 回答体含 answer、decision、reason；已关闭/已过期/锁占用 → 409；不存在或越界 → 404 |

- 回答流程：校验关注存在 → 校验工单空间可见 → 工单闸门串行 → 条件更新落库回答 → 提交后恢复会话 → 释放；领域状态错误统一映射冲突。
- 卡片动作：经 Lark Source 的回调入口进入（design.md 8.4、9.2），按同一回答用例处理，不新增第二套闸门逻辑。
- 可见性判定只消费平台权限域的成员关系，不复制到 guard；缺权限点 403、资源不可见 404（design.md 5.7）。

| 队列               | 用途                 | 语义                                                       |
| ------------------ | -------------------- | ---------------------------------------------------------- |
| `notify.pending`   | 提醒、升级、卡片更新 | 低优先级；按关注维度幂等，重复扫描不重复发送               |
| `effect.pending`   | 通知与闸门结果送达   | 事务内只入队、提交后执行；按消息幂等；永久失败 gone 并告警 |
| 周期推进（passes） | 到期、提醒、停滞扫描 | 单次只跑一个 pass；请求合并到下一轮                        |

错误统一 problem+json 并保留 code、status 与 traceId；鉴权失败 401、越权或范围拒绝 403、不存在 404、状态冲突 409；通知发送失败保留待办并重试。

### B4 运行时与框架

Attention 生命周期与闸门判定都在 Engine，送达交给 Notices，外发交给 Outbox 与 Channel（design.md 2.3、4.4、5.6）。

| 项       | 设计                                                                                                                                                                                                                                              |
| -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 两段式   | ① Engine 事务写关注（待答、截止时间）；② 会话侧 workflow 挂起，携带关注标识、问题、选项与恢复标签；③ 人回答：事务内条件更新待答 → 已回答（重复回答 409）→ 恢复会话；④ 超时：扫描截止时间 → 已过期 → 生成 24h 复查关注 → 取消运行（design.md 4.4） |
| 事实源   | 关注表是唯一事实源；会话工作流挂起只承载等待，跨进程恢复按关注重建，不把运行时快照当业务状态（design.md 2.5、5.5）                                                                                                                                |
| 闸门串行 | 同一工单同一时刻只受理一条回答；进程内按工单排队 + 工单级 Redis 锁（SET NX PX、TTL 30s、Lua 值校验释放、故障 fail-open），关注唯一约束与状态校验兜底（design.md 5.4）                                                                             |
| 送达     | 关注创建、提醒、升级经 `application/notices` 投递会话组织语言；对外只经 Outbox → Channel 发送，按消息幂等（design.md 2.3、8.4）                                                                                                                   |
| 提醒     | 截止前 12 小时窗口；一条关注只提醒一次，幂等键按关注维度固定                                                                                                                                                                                      |
| 停滞     | 进行中工单超 24 小时且无待答关注、无活跃派工才生成 24h 复查关注；受策略开关控制（design.md 5.8）                                                                                                                                                  |
| 状态错误 | 已关闭或已过期关注回答统一映射 409；锁占用直接 409；其他按服务端错误处理（见 B6）                                                                                                                                                                 |
| 恢复     | 过期处理失败下一轮重试；重启后未完成扫描按周期推进继续，不重复已完成的提醒（design.md 4.5、5.8）                                                                                                                                                  |

### B5 配置与部署

| 配置                                          | 来源             | 作用                                      |
| --------------------------------------------- | ---------------- | ----------------------------------------- |
| `escalationOwner` / `escalationOwnerBySource` | 当前策略 `rules` | 升级关注的等待对象；缺失回落授权发起人    |
| `watchdogEnabled`                             | 当前策略 `rules` | 关闭时跳过停滞扫描；缺省开启              |
| 默认时限                                      | 代码常量         | 关注 72h、升级/停滞复查 24h、提醒窗口 12h |
| 通知幂等键                                    | 代码常量         | 按关注或工单维度固定，重复扫描不重复发送  |

- 部署：周期扫描与送达只在 worker 进程注册，api 进程不跑周期任务；Redis 不可用时锁降级放行并告警；V0 单实例（design.md 5.2、10.1）。
- 会话挂起依赖运行时持久化能力；运行时不可用时等待退化为「只靠关注回答后人工触发重试」，不回退为自动通过。
