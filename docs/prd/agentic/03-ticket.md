## 二、产品规格（A）

### A1 功能目标与非目标

| 类型   | 内容                                                                                                                                                                                                        |
| ------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 目标   | 平台把外部事件授权成工单：接单在同一事务内产生结论关联、工单、授权、订阅与首个派工，不允许半单；工单只由研判创建；授权不可变，扩范围必须新工单                                                              |
| 目标   | 工单以空间为数据边界，越界不可见；执行器崩溃或重启不改变工单状态；派工按全局队列排队，同一工单同时只有一个活跃执行；执行不设单次 token、时长或工具次数上限，改用停滞检测、取消与成本可观测兜底              |
| 非目标 | 不判断「要不要做」（属 02）、不执行任务的模型选择、不写产物版本、不渲染卡片与提醒、不管理空间成员与角色授予（属平台权限域）；不做跨空间单一工单、不做授权原地扩范围、不做跨实例移交；本期不接入具体业务场景 |

### A2 角色与入口

| 角色       | 可观察行为                                                         |
| ---------- | ------------------------------------------------------------------ |
| 请求人     | 看到自己发起的工单、未决问题与产物草稿；不能结束、重开或改授权     |
| 空间负责人 | 本空间内查看全部工单与线程；有更新权限时可结束与重开；可读运行轨迹 |
| 平台管理员 | 不受空间限制，可见全部工单与线程                                   |
| Engine     | 接单、派工、推进工单状态并写关注；是工单状态的唯一写者             |
| Executor   | 经内部执行契约领取运行、追加回报；不直接对人说话，不直接改业务表   |
| Source     | 经内部契约与 Channel 写回报与通知；权限之外不产生任何写操作        |

入口：工单列表页、工单详情页、线程页（人）；内部执行契约（Executor）；研判接单（上游，唯一建单入口）。

### A3 功能逻辑与判定

#### A3.1 接单事务

| 步骤 | 动作                                                                   | 判定与失败分支                                                               |
| ---- | ---------------------------------------------------------------------- | ---------------------------------------------------------------------------- |
| 1    | 校验线程与工单的空间归属                                               | 线程有空间而工单空间不一致 → 拒绝建单，不写任何记录                          |
| 2    | 由研判结论构造授权、工单、订阅与首个派工                               | 策略版本非正整数、发起人为空、授权范围为空 → 拒绝建单                        |
| 3    | 结论关联、授权、工单、订阅与首个派工一次写入；提交后才入队派工并写审计 | 写入失败整体回滚；入队失败不回滚接单，派工记录保留，由周期推进重试或人工兜底 |

#### A3.2 生命周期、授权与派工

| 状态  | 进入方式                         | 可执行动作                               |
| ----- | -------------------------------- | ---------------------------------------- |
| open  | 接单；已结束工单被重开           | 派工、执行、写关注、结束；查看轨迹       |
| ended | 人结束、最终回报就绪、驳回后结束 | 只读；有权限者可重开；不能派工或回滚产物 |

- 结束与重开必须有 1–500 字原因；重复结束幂等并保留首次信息；重开沿用原授权与订阅，不生成新工单。
- 授权不可修改：范围变大、目标变化或强度升级 → 新开工单并生成新授权；结束不删除授权与订阅。
- 订阅与派工：接单自动订阅来源线程（原因「开单」），同一工单同一线程只一条，只给上下文、不校验发送者、不授权；只对进行中工单派工，同一工单同时只一个未结束绑定，已有则复用并以租约续期；每次重试尝试序号递增；开始必须携带执行运行标识，同一运行重复开始幂等，已被其他运行占用则拒绝；派工中断后新绑定必须带恢复说明。
- 失败分支：原因为空或超长拒绝结束；不存在按不存在处理；进行中重开无副作用；重复订阅被联合主键拒绝；已结束工单派工被拒；空运行标识与不存在的绑定被拒。

#### A3.3 执行面、停滞与取消

| 项       | 规则                                                                                                |
| -------- | --------------------------------------------------------------------------------------------------- |
| 执行环境 | 一工单一会话一目录；运行在沙箱内，沙箱默认不开放宿主能力；工作区准备失败可重试，重试耗尽转关注      |
| 会话     | 持久或事件式会话，运行标识即派工的执行标识；上下文与记忆只是可重放缓存，业务事实不写入其中          |
| 上限     | 不设单次执行的 token、时长与工具次数上限；风险由停滞检测、取消、成本可观测与组织级配额承接          |
| 停滞     | 会话在阈值内无回合进展 → 判定停滞并写关注；取消只结束当前运行，工单保持进行中，取消后不得再投递输入 |
| 工具     | 工具调用必须校验能力令牌，能力、范围与时间窗由派工签发；子代理只能获得父级令牌的子集                |

- 失败分支：沙箱或工作区不可用 → 按可重试错误退避；会话启动失败 → 转关注并保留派工记录；取消与停滞重复判定不产生第二条关注。
- 只读事实：工单状态独立于执行会话，会话崩溃或重启不回滚工单，也不改写授权与订阅。

#### A3.4 执行回报语义

| 回报类型         | 对执行绑定的影响 | 对工单的影响                                        |
| ---------------- | ---------------- | --------------------------------------------------- |
| progress/waiting | 只追加，不改状态 | 只追加轨迹                                          |
| ready            | 结束绑定         | 结束工单，原因取回报摘要，缺省「Executor 报告就绪」 |
| blocked          | 结束绑定并记原因 | 保持进行中并移交人工；已有未关闭复核关注时不重复    |
| failed           | 结束绑定并记原因 | 与 blocked 相同；工单已结束则跳过移交               |

- 失败分支：progress/waiting 不得结束工单；重复最终回报幂等；负载无摘要时用缺省文案，不把回报正文当结构化字段解析。
- 停滞与取消由系统侧判定，不产生回报事实；取消后到达的回报按冲突处理，不推进工单。

#### A3.5 可见性与空间成员

- 空间是数据可见性边界：工单、线程、关注与产物都归属一个空间；平台管理员不受空间限制，普通用户只可见自己作为成员所在的空间。
- 空间、成员关系与角色授予由平台权限域维护；本域只消费判定结果，不保存成员关系，也不提供成员管理入口。
- 成员管理支持列表、授权、撤销，同一用户同一空间只一条关系；权限不足拒绝并留审计，撤销不存在关系返回未删除。
- 越界读取：列表不出现，详情与轨迹按「不存在」处理，不泄漏存在性；越界写操作同样按不存在处理。

### A4 状态与数据流转

| 对象      | 状态与流转                             | 说明                                     |
| --------- | -------------------------------------- | ---------------------------------------- |
| 工单      | open → ended；ended → open（人工重开） | 状态独立于执行会话；结束不删除授权与订阅 |
| 授权      | 创建后不变                             | 扩范围 = 新工单；策略变更不改写历史授权  |
| 执行绑定  | pending → running → ended              | 每次重试一行；同一工单同时只一个活跃行   |
| 订阅/回报 | 创建后保留                             | 订阅只给上下文；回报只追加               |

```
研判 accept ─▶ 接单事务（结论关联 + 工单 + 授权 + 订阅 + 首个派工）
  ─▶ 调度器入队派工 ─▶ 工作区准备 + 持久会话启动 ─▶ 执行
  ─▶ ready 结束工单｜blocked/failed 保持 open 并转关注｜停滞/取消保持 open 并转关注
  ─▶ 关注回答（见 04）─▶ 确认继续、修改后继续或驳回结束
```

不变量：I1 只有研判能创建工单；I2 授权不可变、扩范围新工单；I3 订阅不授权；I5 工单状态独立于执行器；I6 不存在跨空间的单一工单。

### A5 交互与异常

| 场景     | 可观察行为                                                                                                              |
| -------- | ----------------------------------------------------------------------------------------------------------------------- |
| 工单列表 | 状态（全部/进行中/已结束）、空间筛选、按开启时间或超时优先排序；筛选写入地址栏；按开启时间倒序、默认 50 条、最多 100 条 |
| 工单详情 | 显示状态、类型、空间、授权摘要、产物、未关闭关注与派工记录；轨迹需审计权限、可按时间点回放、敏感字段掩码                |
| 结束重开 | 进行中显示原因输入，原因为空禁用提交；已结束显示原因与重开按钮                                                          |
| 线程详情 | 事件按时间排列，带来源与过滤原因；显示线程关联工单与显式冲突标记                                                        |

异常：工单不存在或不可见 → 按不存在提示；原因为空或超长 → 提示补充；已结束再结束、进行中再重开 → 幂等成功；并发结束/重开 → 后到请求不产生第二条状态事实；分页参数非法 → 提示范围；权限不足 → 按所需权限提示，前端同时隐藏不可用操作。

### A6 扩展与接入点

**数据接入点**

- 研判接单：结论、空间、强度、发起人、策略版本；唯一建单入口，同事务写工单、授权、订阅与首个派工。
- 闸门回答与内部执行契约：确认/修改/驳回与答案；创建运行、追加回报；回报只追加，不直接改授权。
- 来源线程事件：线程后续事件；只按订阅扇出上下文，不触发建单、不授权。

**扩展点**：工单类型（新增取值并同步校验、展示与筛选）；订阅原因（新增须声明扇出语义，仍不授权）；Executor（实现执行端口接入，不反向依赖业务表）；回报类型（声明是否终止性，非终止不得改变工单状态）；空间与成员（复用平台权限域的同一套判定）。**接入约束与禁止项**：禁止绕过研判直接建单；禁止接单事务外补写工单/授权/起始订阅；禁止原地修改授权；禁止合并多空间为一张工单；禁止把订阅当授权；禁止改写授权、回报等只追加事实；禁止 Executor 直写业务表；禁止用 progress/waiting 结束工单；所有写操作必须带身份、依据与审计。

### B2 数据表

本域归属 5 张表；全量表清单与归属见 [design.md](design.md) 7.2，字段级定义以 Prisma schema 为准；接单事务写授权、工单、订阅与第一个派工，任一步失败整体回滚；授权、回报、订阅只追加，工单与派工有状态，派工每次重试一行、尝试序号递增。

| 表                      | 关键字段                                                                                                | 约束与索引                                                                       | 保留        |
| ----------------------- | ------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------- | ----------- |
| `agentic_tickets`       | id、spaceId、mandateId、threadId、kind、status、openedAt、endedAt、endReason                            | mandateId 唯一；`(threadId,status)`、`(spaceId,status)`、`(status,openedAt)`     | 结束后 1 年 |
| `agentic_mandates`      | id、policyId、policyVersion、strength、scope、actorId、actorUserId、sourceType、matchedRules、createdAt | 策略外键 Restrict；`(actorUserId,createdAt)`、`(policyId)`                       | 永久        |
| `agentic_assignments`   | id、ticketId、status、attempt、executorRunId、leaseExpiresAt、startedAt、endedAt、error、recoveryNote   | executorRunId 唯一；`(ticketId,status)` 部分唯一（单活跃）、`(status,updatedAt)` | 180 天      |
| `agentic_subscriptions` | ticketId、threadId、reason、createdAt                                                                   | `(ticketId,threadId)` 联合主键；`(threadId)`                                     | 随工单      |
| `agentic_reports`       | id、assignmentId、kind、payload、createdAt                                                              | `(assignmentId,createdAt)`；绑定外键 Cascade                                     | 180 天      |

- 空间与成员属 iam（见 PRD-IAM），本域只保存 spaceId 引用，不复制可见性事实源。

### B3 接口与队列

| 方法与路径                                                          | 权限/鉴权               | 行为与失败分支                                                                 |
| ------------------------------------------------------------------- | ----------------------- | ------------------------------------------------------------------------------ |
| `GET /agentic/tickets`                                              | `agentic.ticket:read`   | status/spaceId/limit（默认 50、上限 100）；按空间可见性过滤                    |

| `POST /agentic/tickets/:id/end`、`POST /agentic/tickets/:id/reopen` | `agentic.ticket:update` | end 原因 1–500、重复结束幂等；reopen 仅 ended 生效、open 重开幂等              |

| `POST /internal/artifacts`                                          | 能力令牌                | 写产物并绑定 assignmentId；产物版本链归属 05                                   |

- 空间与成员端点归 iam（见 PRD-IAM），本域只消费可见性判定，不提供成员管理端点。

| 队列               | 用途                                   | 语义                                                                 |
| ------------------ | -------------------------------------- | -------------------------------------------------------------------- |
| `assign.pending`   | 工作区准备、会话启动、输入投递         | 同工单单活跃派工；事务内只入队、提交后执行；错误分类后指数退避与抖动 |
| `effect.pending`   | 回执与产物出站                         | 按 kind 与 key 唯一；提交后执行；暂停时保留待执行记录                |
| 周期推进（passes） | 中断派工恢复、停滞检测、到期与失败复核 | 单次只跑一个 pass；请求合并到下一轮；未知失败进 dead-letter          |

错误统一 problem+json 并保留 code、status 与 traceId；鉴权失败 401、能力令牌拒绝 403、资源不可见 404、状态冲突 409；内部契约拒绝写审计。

### B4 运行时与框架

Engine 是唯一写者；执行只发生在 Session 与 Workspace 内，执行层不写领域表（design.md 2.5、5.5）。

| 项         | 设计                                                                                                                                                                                                                                 |
| ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 装配与接单 | api 与 worker 同镜像双入口；`application/runtime` 装配 Engine、Scheduler、Ports、Sessions、Workspace、Effects、Passes；accept 由 Engine 单事务写结论关联、授权、工单、订阅与首个派工，提交后入队派工（design.md 4.1、4.6、5.2、6.2） |
| 调度       | 全局唯一 Scheduler 处理全部 Trigger 派生工作，不按 Source 拆分；入口只做廉价持久化与入队；派工按优先级（互动 > 普通 > 后台）、按空间的 deficit round robin 公平、同工单单活跃互斥、心跳租约与水位降级推进（design.md 5.3）           |
| 执行       | Mastra durable / evented；一工单一会话一目录；工作区与沙箱按派工解析，沙箱默认不开放宿主能力；执行器只经端口访问（design.md 5.5、8.5）                                                                                               |
| 上限       | 不设单次执行的 token、时长或工具次数上限；以停滞检测、取消、成本归集与组织级配额承接风险（design.md 5.9、5.10）                                                                                                                      |
| 回报推进   | `/internal/reports` 追加 progress/waiting/ready/blocked/failed；Engine 条件更新推进派工与工单，终态幂等（design.md 4.4、4.6）                                                                                                        |
| 恢复与并发 | Passes 扫描租约过期的派工，标记中断并带恢复说明与未读输入重建；同一工单同时只一个活跃派工，Redis 锁与部分唯一索引双保险（design.md 4.5、5.4）                                                                                        |

| 端口          | 方法                                          | 约束                                        |
| ------------- | --------------------------------------------- | ------------------------------------------- |
| ExecutorPort  | start / deliver / stop                        | 一工单一会话一目录；可恢复（design.md 8.5） |
| SessionPort   | open / resume / deliver / onTurnEnded / close | 只经 Engine 回调写状态                      |
| WorkspacePort | prepare / variables / acquireSlot / release   | 目录与环境隔离；失败可重试                  |

### B5 配置与部署

| 配置                                                              | 来源                | 作用                                           |
| ----------------------------------------------------------------- | ------------------- | ---------------------------------------------- |
| 能力令牌签发密钥、动作上限与有效期                                | 环境变量 + 当前策略 | 内部契约鉴权；绑定派工、空间、工单与工具白名单 |
| `SANDBOX_DRIVER`                                                  | 环境变量            | 沙箱实现选择（Docker / 远程）                  |
| `stagnationThreshold`、`stagnationAction`                         | 当前策略 `rules`    | 停滞判定阈值与处置（只写关注 / 写关注并取消）  |
| `escalationOwner` / `escalationOwnerBySource`、`permissionWindow` | 当前策略 `rules`    | 失败/停滞关注等待对象与内部写时间窗            |

- 部署：api 与 worker 同镜像双入口，worker 装配调度器、Sessions、Workspace、Effects、Passes；生产必须注入能力令牌签发密钥，缺失时内部端点按未启用处理，不降级为公开；V0 单实例（design.md 5.2、10.1）。
