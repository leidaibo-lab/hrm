## 二、产品规格（A）

### A1 功能目标与非目标

| 目标       | 说明                                                          | 平台指标                                       |
| ---------- | ------------------------------------------------------------- | ---------------------------------------------- |
| 决策可解释 | 每条结论带策略版本与依据，四态明确                            | 结论带策略版本与依据的比例 100%                |
| 不误建单   | 只有通过确定性准入与模型研判的接单才创建工单与授权            | 未通过研判而建单 0；unavailable 被当作接单 0   |
| 不重复研判 | 同一 Thread 同一时刻只跑一次研判，期间到达的事件合批          | 同 Thread 并发研判 0；每批只产生一个结论       |
| 成本可控   | 硬过滤、Gate 与订阅直通在接入链路内联完成，只有慢路径调用模型 | 直通事件模型调用 0；未通过准入的事件模型调用 0 |
| 边界清晰   | 研判与接单只在事件所属空间内完成，越空间不读取、不建单        | 跨空间建单 0；越空间读取 0                     |

非目标：本期不接入具体业务场景（业务能力由后续 AgentSpec 接入），只交付 Super-agent 平台能力；不执行任务、不做任务内容加工；不写产物、不写回；不推进工单状态与人工闸门；不管理权限点、用户与空间（空间由 iam 维护）；不配置模型供应商（只引用模型档位）；不做知识库与跨实例协作；不做多租户与部门，不引入关系型资源授权服务（空间可见性只按 Space 成员关系判定）。

| 角色                 | 入口                                   | 权限点                                     | 可做什么                                                          | 不可做什么                         |
| -------------------- | -------------------------------------- | ------------------------------------------ | ----------------------------------------------------------------- | ---------------------------------- |
| 平台管理员           | 控制台策略页（当前版本、准入表、发布） | `agentic.policy:update`                    | 发布策略版本、维护准入表、配置名单与模型档位                      | 不代替研判直接建单；不能改历史结论 |
| 请求人               | 无独立入口，事件经 Source 接入         | 无平台权限点                               | 触发研判；被名单识别后更容易被受理                                | 不能指定结论；不能查看他人空间数据 |
| 负责人               | 工单时间线、审计记录                   | `agentic.ticket:read`/`agentic.audit:read` | 查看结论、依据、策略版本与调度记录                                | 不能改结论；不能绕过审批恢复流程   |
| Engine（系统）       | 内联过滤、triage 队列消费与研判端口    | —                                          | 硬过滤与 Gate 内联、线程锁、合批、落 Decision、accept 单事务      | 不执行任务；结论不经 Engine 不落库 |

| Executor（系统）     | 不参与研判，消费后续工单               | —                                          | 按工单执行并回报                                                  | 不产出 Decision；不读写策略        |
| Source（插件，系统） | 事件接入端点                           | —                                          | 提供事件、线程键、范围与发起人；维护事件流                        | 不判断接不接；不写 Decision        |

### A3 功能逻辑与判定

#### 3.1 三级过滤与快慢路径

| 阶段     | 位置                     | 内容                                                           | 调模型 | 结果                                 |
| -------- | ------------------------ | -------------------------------------------------------------- | ------ | ------------------------------------ |
| 硬过滤   | 接入链路内联             | 验签、自身消息、空文本、实例停用、授权失效、重复幂等键、跨空间 | 否     | 丢弃或返回重复，不进入慢路径         |
| Gate     | 接入链路内联（策略快照） | 名单、点名、准入单元格                                         | 否     | pass 或 filtered，写 disposition     |
| 订阅直通 | 接入链路内联             | 已订阅 Thread                                                  | 否     | fanned_out，signal 给存活 assignment |
| 慢路径   | triage 队列              | 线程锁 + 合批（≤50）+ Assessment                               | 是     | Decision                             |

- 前三级全部在接入请求链路内完成，入口只做廉价持久化、内联判定与入队；只有需要模型的慢路径进入队列。
- Gate 策略快照未命中时降级为入 triage 再判，保证正确性；订阅直通不产生 Decision、不调用模型。

#### 3.2 策略与准入规则

| 规则     | 说明                                                                                 | 失败分支                                   |
| -------- | ------------------------------------------------------------------------------------ | ------------------------------------------ |
| 版本化   | 每次发布生成新版本、版本号递增；已发布版本不可修改，旧版本继续服务已存在的授权与结论 | 版本号冲突由唯一约束兜底；修改请求不接受   |
| 规则内容 | 受理强度、名单、模型档位、写回字段、升级负责人、时间窗、停滞阈值、回归阈值等         | 未知键透传保留，不认识的键不参与判定       |
| 准入表   | 按「空间 + 源实例 + 范围行 + 单元格」配置允许/拒绝；同一单元格唯一                   | 重复单元格拒绝发布；任一条非法则整批不写入 |

#### 3.3 确定性准入（Gate）

程序准入只做确定性判定，不调用模型。名单内成员被点名视为显式调用，直接通过；其余按准入表单元格判定。

| 输入情形                | 判定单元格                                                     | 结果                                 |
| ----------------------- | -------------------------------------------------------------- | ------------------------------------ |
| 在名单且被点名          | 无（直通）                                                     | 通过，记录策略与版本                 |
| 其余三类组合            | listed_unaddressed / unlisted_addressed / unlisted_unaddressed | 按对应单元格规则允许或拒绝           |
| 无准入规则 / 无当前策略 | —                                                              | 过滤，原因分别记「无规则」「无策略」 |

- 通过准入后进入合批与研判；未通过的事件置为 filtered 并保留原因，不产生结论、不调用模型。
- 失败分支：名单解析失败视为不在名单；准入表缺失按「无规则」处理；跨空间事件直接过滤；判定过程异常交队列重试。

#### 3.4 订阅直通

- 命中条件：事件所属 Thread 存在任一订阅。
- 处理边界：事件置为 fanned_out 并直接扇出，不进入 Gate 之后的模型路径、不调用模型、不产生 Decision；订阅只给上下文不授权，扇出不校验发送者，结束工单保留订阅，已处置事件跳过。
- 失败分支：扇出失败由调度器重试；权限与写操作由执行侧判定。

#### 3.5 线程锁与合批

- 串行：同一 Thread 同时只允许一次研判；后来者等待锁，等待超时交队列重试。
- 合批：取得锁后把同 Thread、同空间、同来源的 pending 事件按发生时间升序合批，单批上限 50；批内只产生一个结论。
- 降级：已处置事件不重复参与研判，队列重复投递不产生第二个任务；锁服务不可用时放行并告警，可能并发研判需按结论记录核对。

#### 3.6 全局调度器与慢路径队列

- 单一组件：全局唯一的调度器处理所有 Trigger 派生的阶段工作，不按 Source 拆实例、不做每来源独立队列。
- 优先级：interactive（人正在等）> normal > background；公平：按空间的 deficit round robin，防止单空间饿死其他空间。
- 互斥：同一 Thread 单次研判；同一工单单活跃执行（租约与唯一约束双保险）；租约由 worker 心跳续租，过期回收并触发恢复。
- 水位与背压：积压高时延迟派发、暂停后台任务并告警；入口只在硬水位拒绝或断开；暂停时保留待执行记录。
- 重试：错误分类（可重试/永久/未知），指数退避与抖动，未知进 dead-letter；事务内只入队，提交后执行。
- 边界：调度器不承担模型供应商配额，配额、限流与失败转移由模型网关负责，调度器只消费容量与降级信号。

#### 3.7 模型研判（Assessment）

| 项       | 规则                                                                                                                                                                  |
| -------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 输入     | 本批事件（文本、发起人、点名、发生时间）、Thread 标识、事件所属空间、当前策略与版本                                                                                   |
| 输出     | 结论四态之一、授权强度、范围建议、命中依据、结论说明、工单类型建议                                                                                                    |
| 工具     | 只允许读 Thread/工单与检索相似历史工单，按空间过滤；越权内容不进入上下文；不引入知识库                                                                                |
| 运行方式 | 持久执行会话；按策略解析 fast/main/judge 档位为逻辑模型，限流、429、失败转移与计量由模型网关承担                                                                      |
| 护栏失败 | 外部文本按不可信处理；注入检测命中即中止；PII 脱敏；输出按 schema 校验；未配置模型或调用失败返回 unavailable 并保留原因；输出非法或缺依据时交队列重试，耗尽后人工核对 |

#### 3.8 决策四态与接单

| 结论        | 含义                          | 下游动作                                                               | 是否建单 |
| ----------- | ----------------------------- | ---------------------------------------------------------------------- | -------- |
| accept      | 接单                          | 原子创建结论、授权、工单、订阅与首个派工，提交后入队派工并投递后续任务 | 是       |
| stop        | 明确不做                      | 只记录结论，结束本次研判                                               | 否       |
| ignore      | 与本任务无关                  | 只记录结论，静默结束                                                   | 否       |
| unavailable | 未完成研判（模型/策略不可用） | 记录原因与策略版本，保留事件供人工复查                                 | 否       |

- 四条结论都必须带策略版本与依据（原因或命中规则），否则不允许落库；接单范围必须落在事件所属空间与 Thread 范围内，跨空间一律拒绝建单并整体回滚。
- 授权不可变：扩范围即新工单；订阅不授予权限。

#### 3.9 策略生效与在办工单

- 发布即新版本，版本号递增；已发布版本不可修改，旧版本继续服务已存在的授权与结论。一次研判使用开始时的策略版本并写入结论；版本冲突由唯一约束兜底。
- 变更投递给在办工单：后续输入按当前版本复核；不撤销已发授权、不改写历史结论。

### A4 状态与数据流转

| 对象     | 状态                                        | 流转                                                                                          | 触发者 |
| -------- | ------------------------------------------- | --------------------------------------------------------------------------------------------- | ------ |
| Trigger  | pending / filtered / evaluated / fanned_out | pending → filtered（未准入）；pending → evaluated（已研判）；pending → fanned_out（订阅直通） | Engine |
| Decision | accept / stop / ignore / unavailable        | 创建即终态，不可修改                                                                          | Engine |
| 策略规则 | 版本化发布；准入表随版本不可变              | 新版本发布后成为当前版本并保留旧版本；准入表只对新版本发布                                    | 管理员 |
| 评估锁   | 空闲 / 占用                                 | 取锁 → 合批 → 研判 → 释放；等待超时交队列重试                                                 | Engine |

| 链路         | 输入                          | 变化                                               | 输出                     | 失败分支                                         |
| ------------ | ----------------------------- | -------------------------------------------------- | ------------------------ | ------------------------------------------------ |
| 消费研判任务 | 研判任务 + 判定上下文         | 已处置事件跳过                                     | 进入直通、Gate 或慢路径  | 任务失败交队列重试                               |
| 订阅直通     | Thread 订阅 + 事件            | 事件 → fanned_out                                  | 扇出订阅者               | 扇出失败重试，事件不回退                         |
| 确定性准入   | 空间 + 源实例 + 范围行 + 名单 | 事件 → filtered 或进入合批                         | 准入结果与原因           | 无策略/无规则/规则拒绝 → 过滤                    |
| 合批与研判   | Thread + 事件批次 + 策略      | 事件 → evaluated；生成 Decision；accept 时原子落库 | Decision、工单（必要时） | 锁超时/结论缺依据 → 重试；接单任一步失败整体回滚 |
| 调度派发     | 待处理任务 + 优先级/公平/水位 | 任务出队、占用并发槽与租约                         | 研判或派工任务进入执行   | 水位高延迟派发；租约过期回收并恢复               |
| 策略发布     | 新版本规则与准入表            | 新版本成为当前；在办工单后续输入按新版本复核       | 版本视图、审计           | 重复单元格/非法规则整批拒绝                      |

### A5 交互与异常

| 场景                                              | 对用户/上游表现 | 系统处理                                                    | 可观察结果                           |
| ------------------------------------------------- | --------------- | ----------------------------------------------------------- | ------------------------------------ |
| 无策略/无规则/规则拒绝/未点名不在名单；或订阅直通 | 无打扰          | 不调用模型：前者 filtered 保留原因，后者直接扇出 fanned_out | 过滤原因、事件状态、模型调用数不增加 |
| 模型不可用或输出非法                              | 无打扰          | 结论 unavailable 并保留原因，不建单                         | 结论四态、原因、事件 evaluated       |
| 线程锁等待超时 / 结论缺少依据 / 锁服务不可用      | 无用户感知      | 超时或失败交队列重试，事件保持待处理；锁不可用放行并告警    | 队列失败次数、告警记录、事件仍待处理 |
| 接单范围跨空间                                    | 无用户感知      | 拒绝建单并回滚整笔写入                                      | 无工单/授权残留，错误记录            |
| 策略发布重复单元格 / 版本冲突                     | 明确错误提示    | 拒绝发布，整批不写入                                        | 接口错误；当前策略不变               |
| 已处置事件重复消费                                | 无用户感知      | 直接跳过                                                    | 事件与结论数不变                     |
| 暂停期间到达事件                                  | 无打扰          | 记录 Trigger、不启动新评估、不发回复；恢复后按当前策略复核  | 事件状态、暂停开关                   |
| 积压超过水位                                      | 无用户感知      | 延迟派发、暂停后台任务并告警；入口只做硬水位拒绝            | 队列积压、派发延迟、告警记录         |

### A6 扩展与接入点

#### 数据接入点

| 接入点     | 数据                                                                 | 约束                                                 |
| ---------- | -------------------------------------------------------------------- | ---------------------------------------------------- |
| 研判任务   | Trigger 主键、空间、实例、范围行、点名、发起人、来源、范围、发生时间 | 事件必须仍待处理；已处置直接跳过                     |
| 策略与准入 | 规则阈值；准入表；Thread 标识、订阅关系与事件批次                    | 版本化、准入表随版本不可变；上下文只读、不写业务状态 |
| 研判回调   | 候选结论、依据、强度与范围建议                                       | 只经 Engine 落库；不得直接写业务表                   |

#### 扩展点

| 扩展轴       | 接入方式                                         | 必须满足                                           |
| ------------ | ------------------------------------------------ | -------------------------------------------------- |
| 新规则与准入 | 新增规则键或准入单元格/判定维度并接通消费方      | 版本化、可审计；确定性判定、不调用模型、原因可追溯 |
| 模型档位     | 按策略解析 fast/main/judge，AgentSpec 只声明档位 | 不写死型号；解析失败不得静默降级为无模型执行       |
| 评估器       | 实现模型研判端口替换研判实现，不改线程锁与合批   | 结论 schema 与护栏不降级；只经 Engine 落库         |

#### 接入约束与禁止项

- 只有研判能创建工单与授权；订阅只给上下文不授权；同一 Thread 同时只允许一次研判，不得绕过线程锁。
- 不得跳过 Gate 直接调用模型；订阅直通与确定性准入不得调用模型；低置信或不可用不得自动接单。
- 研判不得写业务状态、产物、外部副作用；不得把执行器状态当作工单状态；不得跨空间建单；不得用自由文本推断「等待人」或审批结果。

### A7 验收要点

> 复选框：`[ ]` 待评审/未开始，`[x]` 已验证；每条含期望、证据与评审人。

**过滤与准入**
- [ ] AC-02-01 无策略与无规则：事件 filtered 并保留原因；不产生结论、不调用模型。（证据：事件处置与过滤原因、结论数；评审人：待指定）
- [ ] AC-02-02 确定性准入：名单内点名直通；其余按单元格允许或拒绝，拒绝原因可查，判定不调用模型。（证据：准入结果、过滤原因、模型调用数；评审人：待指定）

**研判与接单**
- [ ] AC-02-03 订阅直通：事件 fanned_out；不调用模型、不产生新结论、不产生新工单。（证据：事件状态、订阅记录、结论数、模型调用数；评审人：待指定）
- [ ] AC-02-04 决策四态：四态正确落库；仅 accept 建单；unavailable 带原因不建单。（证据：结论记录、工单数、时间线；评审人：待指定）
- [ ] AC-02-05 接单原子性：结论、授权、工单、订阅与首个派工同时存在；任一步失败无半单。（证据：五类记录一致性；评审人：待指定）

### B3 接口与队列

| 方法 | 端点                                    | 权限                    | 行为与失败分支                                            |
| ---- | --------------------------------------- | ----------------------- | --------------------------------------------------------- |
| GET  | `/agentic/policies/current`             | `agentic.policy:update` | 当前版本与准入摘要；无策略时为空                          |
| POST | `/agentic/policies`                     | `agentic.policy:update` | 发布新版本；规则为空/结构非法 400；版本冲突由唯一约束兜底 |
| GET  | `/agentic/policies/:id/admission-rules` | `agentic.policy:update` | 该版本准入行；策略不存在时为空                            |
| POST | `/agentic/policies/:id/admission-rules` | `agentic.policy:update` | 整批写入；重复单元格/策略不存在 → 拒绝且整批不写入        |

策略发布与准入表发布写审计（`policy.publish`、`policy.publish_admission`），记录操作者、空间与版本。

| 队列             | job                           | 生产方                  | 消费方                   | 并发/顺序                            | 负载要点                                                            |
| ---------------- | ----------------------------- | ----------------------- | ------------------------ | ------------------------------------ | ------------------------------------------------------------------- |
| `triage.pending` | 慢路径研判（按 Trigger 幂等） | Engine.Intake（内联后） | Engine.Evals（worker）   | 同 thread 串行；重试 2 次、退避 5 秒 | spaceId、triggerId、threadId、来源、范围行、点名、发起人、发生时间  |
| `accept.pending` | 建单事务                      | Engine.Evals（accept）  | Engine.Tickets（worker） | 唯一约束兜底                         | spaceId、decisionId、mandate、ticket、subscription、首个 assignment |

本域不自建队列；消费入口先判 Trigger 是否待处理、暂停开关与线程锁，重试耗尽后保持 pending，由周期推进再次入队并核对；jobId 由业务主键派生并经队列适配器净化，重复投递只保留一个任务。

### B4 运行时与框架

| 项         | 设计                                                                                                             |
| ---------- | ---------------------------------------------------------------------------------------------------------------- |
| 唯一写者   | 只有 Engine 写领域表；router 会话只产出研判候选，经回调由 Evals 落库                                             |
| 三级过滤   | 入口只做廉价持久化与内联判定：硬过滤 → Gate（策略快照）→ 订阅直通；Gate 快照未命中降级入 triage 再判             |
| 全局调度器 | 单逻辑组件处理所有 Trigger 派生阶段工作，不按 Source 拆分；优先级、空间公平、互斥、租约、水位、重试、dead-letter |
| 线程锁     | Redis SET NX PX，TTL 覆盖一次 Eval，值校验释放；等待上限 60 秒、重试间隔 100 毫秒；锁不可用放行并告警            |
| 合批       | 取锁后同 Thread、同空间、同来源 pending 事件按 occurredAt 升序，单批上限 50；批内只产生一个 Decision             |
| Gate       | `domain/policy` 确定性判定：名单内点名直通；其余三单元格查准入表；无策略/无规则 filtered 并保留原因              |
| Assessment | router AgentSpec：档位解析 fast/main/judge、结构化输出 schema、持久执行包装、注入检测与 PII 脱敏                 |
| accept     | 单事务写 Decision、Decision 关联、Mandate、Ticket、Subscription 与首个 Assignment；提交后入队派工                |
| 失败与降级 | 模型不可用 → unavailable；输出非法重试后人工核对；锁不可用 fail-open；暂停期间不启动新 Eval                      |
| 背压与配额 | 调度器只消费容量与降级信号，不实现 provider 配额；积压高时延迟派发、暂停后台任务并告警                           |
| 成本与上限 | 不设单次执行的 token、时长或工具次数上限；成本经模型网关计量并按空间与 Agent 归因，以停滞检测与取消控制风险      |
| Watchdog   | 评估超时重新入队；连续失败进入健康异常；结论缺策略版本或依据拒绝落库                                             |

### B5 配置与部署

| 配置         | 来源/默认                                                         | 作用                                         |
| ------------ | ----------------------------------------------------------------- | -------------------------------------------- |
| 策略版本     | 策略表；通过发布接口变更                                          | 只追加；旧版本继续服务存量授权与结论         |
| 名单         | 策略规则 allowedActors / allowedUsers                             | 为空表示无人在名单；名单内被点名直通         |
| 模型档位     | 策略规则 assessmentModel / fastModel / mainModel / judgeModel     | 只引用逻辑模型；解析失败不得降级为无模型执行 |
| 准入表       | 策略版本内的准入行；按空间、源实例、范围行与单元格写入            | 随版本不可变；重复单元格整批拒绝             |
| 评估锁与合批 | 代码常量：TTL 覆盖一次 Eval、等待 60 秒、重试 100 毫秒、单批 50   | 覆盖一次评估；锁不可用 fail-open             |
| 调度参数     | 队列优先级、空间公平权重、租约时长、水位阈值                      | 全局调度器统一读取；暂停保留待执行记录       |
| 部署         | api 暴露策略接口；worker 消费 triage 与 accept 队列；同镜像双入口 | V0 单实例；暂停期间不启动新评估              |
