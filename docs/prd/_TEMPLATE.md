# <产品/功能名> 需求文档（PRD）模板

> 用法：目录式 PRD 固定三类文件——`index.md`、`design.md`、`NN-<域>.md`；小型需求可用 `index.md` + 功能篇，或单篇合并。模板章节不可删除，无内容写「无」。

```
# <产品/功能名> 产品需求文档

## 一、文档信息
## 二、产品定位与价值
## 三、背景与问题
## 四、目标用户与场景
## 五、范围与非目标
## 六、功能全景
## 七、一页架构
## 八、非功能需求与成功指标
## 九、数据与埋点需求
## 十、验收总览
## 十一、阅读路径与文档索引
## 十二、假设、依赖与里程碑
## 十三、开放问题
## 十四、变更记录
```

## 写作要求

- 一篇只回答一个问题；跨篇只引用不复述。
- 产品段（A 段、index）只写可观察行为，禁止实现词与代码路径；B 段只写本域实现，禁止进度词。
- 验收统一用复选框列表，按功能分组：`- [ ] AC-XX-NN 场景：期望（证据：…；评审人：…）`；`[x]` 表示已验证，不使用验收表格。
- 主 PRD 与专题文档共用同一版本号；本期统一 `V3.0（2026-11-17）`，后续整份 PRD 统一升版。
- 数据表、接口、文件树：总览归 design.md，明细归功能篇 B 段；每张表只有一个归属篇。
- 技术取舍写 ADR，PRD 只保留编号与一句结论；进度与完成度不进 PRD。
