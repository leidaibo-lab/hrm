## 二、产品定位与价值

模型网关是平台的 provider 域：把多家模型供应商收敛为「逻辑模型 + 候选链」，统一凭据、路由、限流、失败转移、计量、计价与汇率换算。

价值：换供应商不改业务；provider 故障可转移；成本可按空间与 Agent 归因；价格可由人工配置并以目录价兜底；多币种可折算为统一记账口径；凭据集中管理。

## 三、背景与问题

- 业务直接依赖某家供应商的模型名与 SDK，换供应商要改代码。
- 多供应商的限流、429、重试与故障转移各自实现，容易形成重试风暴。
- 成本分散在调用点，无法按空间或 Agent 归集。
- 价格依赖人工维护，缺价时无法计费；多币种无法统一比较。
- 凭据散落在配置与代码里，审计与轮换困难。

## 四、目标用户与场景

| 角色       | 核心诉求                                       |
| ---------- | ---------------------------------------------- |
| 平台管理员 | 接入供应商、维护模型与价格、同步目录、观察健康 |
| 空间负责人 | 查看本空间用量与成本                           |
| agentic    | 按逻辑模型调用，不感知 provider                |
| 调度器     | 消费容量与降级信号做背压                       |

| 编号 | 场景         | 期望结果                                               |
| ---- | ------------ | ------------------------------------------------------ |
| G1   | 接入新供应商 | 配置 provider 与候选，业务不改代码                     |
| G2   | 主供应商故障 | 自动转移到候选，调用成功且用量归因正确                 |
| G3   | 供应商限流   | 请求被限额保护，不形成重试风暴                         |
| G4   | 成本复盘     | 按空间、Agent、模型汇总 tokens、原币成本与统一币种成本 |
| G5   | 人工价格缺失 | 自动使用目录价；目录也无价时明确标记缺失并可对账       |

## 五、范围与非目标

本期范围：provider 与凭据、逻辑模型与候选、路由与失败转移、限流与 429、计量与价格、汇率换算、目录同步、用量与成本报表、运行时适配、控制台读模型。

非目标：不决定何时调用模型；不做任务调度与队列准入；不做业务语义；不做知识库检索；不做预算配额；不做外部汇率源同步；不做多租户。

## 七、一页架构

```
调用方（档位 → 逻辑模型 key、能力要求）
   │
   ▼
model-gateway：逻辑模型 → 候选链（provider + providerModelId）
   │ 启用 / 健康 / 熔断 / 能力 / 优先级
   ▼
mastra：模型调用、重试、fallback、流与工具循环
   │ 成功 / 可重试 / 不可重试 / 429
   ▼
计量与计价（人工价优先、目录价兜底、汇率折算）→ 用量 → 成本报表
```

## 八、非功能需求与成功指标

| 目标   | 指标                           | 目标值                           |
| ------ | ------------------------------ | -------------------------------- |
| 可转移 | 主候选可重试失败时转移成功     | 链内转移可观测                   |
| 可限额 | 超限不形成重试风暴             | 限流错误分类正确；上游调用数受控 |
| 可计量 | 成功调用 100% 有归因尝试记录   | 入队失败可对账并告警             |
| 可计价 | 人工价、目录价、汇率来源可追溯 | 历史成本不因调价或汇率变化重算   |
| 安全   | 日志、控制台、审计无明文凭据   | 0 泄露                           |
| 性能   | 链解析与限流判定开销           | P95 ≤ 20ms（实测目标）           |
| 目录   | 目录价可用性                   | 同步年龄 ≤ 7 天；失败保留旧数据  |

## 九、数据与埋点需求

| 事件                  | 触发时机   | 字段                                            | 用途       |
| --------------------- | ---------- | ----------------------------------------------- | ---------- |
| model_resolved        | 解析候选链 | logicalKey、candidateCount、maxAttempts、picker | 路由质量   |
| model_call_attempt    | 每次尝试   | callId、candidate、status、latency、tokens      | 计量与健康 |
| model_failover        | 发生转移   | fromCandidate、toCandidate、reason              | 可用性     |
| provider_degraded     | 健康降级   | provider、reason、recoverAt                     | 告警与背压 |
| catalog_sync_finished | 目录同步   | status、written、unmatched、age                 | 目录质量   |
| price_missing         | 定价缺失   | candidate、logicalKey                           | 计费对账   |
| fx_missing            | 汇率缺失   | currency、candidate                             | 计费对账   |

## 十二、假设、依赖与里程碑

- 假设：供应商提供 OpenAI 兼容接口；models.dev 可访问且价格单位为 USD / 每百万 token；汇率由管理员维护；调用方可传入空间与 Agent 归因。
- 依赖：agentic 的档位解析、iam 的权限点、平台加密与 Redis、models.dev 外部数据。

| 阶段 | 范围                                       | 计划    |
