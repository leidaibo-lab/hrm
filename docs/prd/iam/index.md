## 二、产品定位与价值

iam 是平台的身份与访问域：管理用户、角色、权限点、Space 与成员，并提供全模块唯一的资源授权判定。它把“谁能做什么”“谁能看哪些数据”“Agent 这段执行凭什么做”分开表达，避免权限判断散落在业务代码与前端。

## 三、背景与问题

- 权限判断散落在 controller、service 与前端，容易出现漏判与越权。
- 角色与数据范围混在一起，导致角色爆炸或数据越界。
- Agent 执行使用系统身份或共享密钥，无法表达“只在这个工单、这个空间、这些工具内”。
- 越权响应泄露资源存在性，形成枚举风险。

## 四、目标用户与场景

| 角色       | 核心诉求                               |
| ---------- | -------------------------------------- |
| 平台管理员 | 维护用户、角色、权限点、Space 与成员   |
| 空间负责人 | 管理本空间成员与可见范围               |
| 普通用户   | 只看到自己有权访问的数据               |
| Agent      | 只能访问能力令牌允许的空间、工单与工具 |

| 编号 | 场景           | 期望结果                           |
| ---- | -------------- | ---------------------------------- |
| I1   | 角色授予与撤销 | 下一请求即时生效，越权立即消失     |
| I2   | Space 成员管理 | 成员可见空间内数据，移出后不可见   |
| I3   | 越权访问       | 按不存在处理，不泄露存在性         |
| I4   | Agent 工具调用 | 令牌范围外的资源被拒绝，拒绝可审计 |

## 五、范围与非目标

本期范围：用户、角色、权限点、Space 与成员、动作权限（CASL）、Space 可见性谓词、资源判定入口、能力令牌。

非目标：不做多租户与组织部门；不引入关系型授权服务（跨空间共享、委派、文档 ACL 本期不做）；不做 SSO；不做审计存储本身（审计属平台横切）。

## 七、一页架构

```
用户登录 → 会话（userId、权限点集合、空间列表）
   │
   ├─ 动作权限：CASL ability（能否调用接口/按钮）
   ├─ 数据可见性：Space 成员关系 → 查询谓词
   ├─ 资源判定：AuthorizationService（对象级，后续可扩展）
   └─ Agent：能力令牌（空间、工单、工具、动作、有效期）
```

## 八、非功能需求与成功指标

| 目标     | 指标                        | 目标值      |
| -------- | --------------------------- | ----------- |
| 即时生效 | 角色/成员变更后下一请求生效 | 无缓存滞后  |
| 不泄露   | 越权读取返回与不存在一致    | 0 差异      |
| 可解释   | 允许/拒绝均有判定依据       | 100% 可审计 |
| 最小权限 | Agent 令牌是任务范围子集    | 0 越界      |
| 性能     | 动作判定与谓词生成开销      | 毫秒级      |
