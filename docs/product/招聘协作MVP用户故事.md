# HRM 人资管理系统——招聘管理模块 MVP 用户故事

- **版本**：0.1
- **状态**：需求草案，待团队评审
- **关联 PRD**：[招聘协作MVP产品需求文档.md](招聘协作MVP产品需求文档.md)
- **设计链接**：暂无，统一标记为“待补充”

## 使用说明

每条故事按 3C 结构编写：Card 是一句话目标，Conversation 是业务约束，Confirmation 是可验证的验收条件。故事按业务能力拆分，尽量保持独立、可估算、可测试；技术任务、数据库设计和接口任务不在本文件展开。

## Epic A：账号与组织

### US-001 创建账号并首次修改密码

**Card**：作为管理员，我希望创建带临时密码的用户账号，以便让团队成员安全进入 HRM。

**Conversation**：管理员填写姓名、邮箱、部门和一个或多个业务角色，并设置临时初始密码。用户首次登录只能进入修改密码流程，修改成功后才可进入工作台。管理员重置密码后，同样需要强制修改。

**Design**：待补充：用户创建、首次改密和密码重置页面。

**Confirmation**：

1. 管理员创建账号时，邮箱唯一性、必填字段和角色必填校验生效。
2. 新用户首次登录后不能跳过改密页面访问其他页面。
3. 新密码符合系统密码规则后，用户才能进入有权限的工作台。
4. 管理员重置密码后，用户下次登录必须再次修改密码。
5. 创建和重置操作记录操作者、时间、目标用户和操作结果。

### US-002 维护用户、部门和多角色

**Card**：作为管理员，我希望维护用户的部门和多个业务角色，以便权限跟随组织关系变化。

**Conversation**：管理员负责创建、禁用用户，维护部门、职位负责人和角色。管理员角色只代表平台配置权限，不自动拥有全部招聘数据权限；用户的业务权限由绑定的业务角色合并计算。部门变更完成后立即生效。

**Design**：待补充：组织和角色管理页面。

**Confirmation**：

1. 一个用户可以绑定多个业务角色，登录后的业务权限为各角色权限的合并结果。
2. 管理员可以禁用用户；被禁用用户不能登录，但历史记录仍保留原用户身份。
3. 用户部门变更保存成功后，新的业务数据范围立即生效。
4. 管理员平台权限不能单独绕过业务数据权限查看简历或下载附件。
5. 用户、部门、职位负责人和角色的新增、修改、禁用均记录审计。

## Epic B：职位管理

### US-101 HR成员登记已发布职位

**Card**：作为 HR成员，我希望把飞书已发布的职位登记到 HRM，以便管理后续候选人。

**Conversation**：HRM 不创建或审批招聘需求。HR成员只在飞书职位发布完成后创建职位，并填写职位名称、部门、招聘人数、用人负责人、HR负责人、职位类型、工作地点、飞书审批申请链接和发布时间。每个职位需要指定一名 HR负责人，且该负责人必须是 HR成员。

**Design**：待补充：职位创建和详情页面。

**Confirmation**：

1. 职位表单校验全部必填字段，招聘人数必须为正整数。
2. 飞书审批申请链接以链接格式保存，并在职位详情中可打开。
3. 创建成功后职位状态为“可招聘”，且可以录入候选人。
4. 重复来源链接或重复建档时系统提示 HR，不能静默创建重复职位。
5. 职位记录保存创建人、创建时间和 HR负责人。

### US-102 关闭和重新打开职位

**Card**：作为 HR，我希望手动同步飞书职位的关闭或重新打开状态，以便控制候选人是否还能新增。

**Conversation**：飞书是职位关闭的来源，HRM 一期不自动同步。HR 在 HRM 中手动调整职位状态。关闭只禁止新增候选人，不终止已有候选人的流程。

**Design**：待补充：职位状态操作和关闭提示。

**Confirmation**：

1. HR 可以将可招聘职位调整为已关闭，并填写或确认关闭原因。
2. 已关闭职位不能新建候选人，创建入口明确提示职位已关闭。
3. 已有候选人的面试、评价、待决策和录用操作不因职位关闭而被阻断。
4. HR 可以将已关闭职位恢复为可招聘，恢复后允许新增候选人。
5. 关闭和恢复记录操作者、时间、前后状态和原因。

## Epic C：候选人管理

### US-201 导入候选人和简历

**Card**：作为 HR成员，我希望把 Boss 直聘候选人直接录入 HRM，以便在一个系统中持续推进候选人。

**Conversation**：一期由 HR成员人工取得并上传简历，不经过飞书云盘。候选人必须关联一个 HRM 职位，且必须有姓名、联系方式、简历、来源渠道和应聘职位。

**Design**：待补充：候选人导入表单和简历预览。

**Confirmation**：

1. 只有 HR 可以创建候选人记录和上传简历。
2. 姓名、联系方式、简历、来源渠道和应聘职位缺一不可时，系统阻止提交。
3. 关闭职位不能新增候选人，候选人只能关联一个应聘职位。
4. 创建成功后候选人阶段为“待筛选”。
5. 系统记录来源标识、导入人、导入时间和简历附件信息。

### US-202 识别和处理重复候选人

**Card**：作为 HR，我希望导入简历时获得重复提示，以便避免重复推进同一候选人。

**Conversation**：姓名和联系方式先做标准化。两者完全一致为强重复；只有姓名相同不判重；联系方式相同但姓名不同提示 HR 判断。默认阈值为一年，按最后一次面试时间计算。HR 可以决定继续保留或合并。

**Design**：待补充：重复提示、候选人对比和合并确认页面。

**Confirmation**：

1. 缺少联系方式时系统拒绝录入，并提示补充联系方式。
2. 姓名和联系方式标准化后完全一致时，系统提示强重复，不自动合并或覆盖。
3. 仅姓名相同且联系方式不同的记录可以正常录入。
4. 联系方式相同但姓名不同的记录提示 HR，由 HR 选择继续录入或合并。
5. 重复提示展示距最后一次面试的时间和默认一年阈值。
6. HR 确认合并后新简历和面试记录覆盖旧记录，旧记录软删除并写入合并审计。

### US-203 查看候选人详情和阶段历史

**Card**：作为招聘参与人，我希望查看有权限的候选人详情和历史，以便基于完整上下文推进工作。

**Conversation**：候选人详情包含简历、联系方式、来源、职位、阶段、邀约、面试、评价和变更记录。HR 可全局查看；用人负责人按部门查看；面试官按被分配职位及评价范围查看。

**Design**：待补充：候选人详情页和阶段时间线。

**Confirmation**：

1. 授权用户可以查看其范围内的完整简历和候选人详情。
2. 未授权用户不能通过列表、详情或直接链接访问候选人资料。
3. 候选人详情展示当前阶段、负责人、最近一次变更和阶段历史。
4. 简历下载只有 HR 允许，下载操作记录审计。
5. 关闭职位后，已有候选人的授权查看权限保持不变。

## Epic D：筛选与邀约

### US-301 按状态规则推进候选人

**Card**：作为招聘责任人，我希望系统按职责控制候选人状态，以便每个阶段有明确负责人。

**Conversation**：状态流程为待筛选、初筛、待邀约、面试中、待决策、录用/淘汰/候选人放弃。候选人进入“初筛”后，需要由用人负责人明确初筛通过，才能进入“待邀约”；不通过进入淘汰，待补充则继续停留在初筛。状态只能正向推进，不能退回；淘汰和候选人放弃不可恢复。

**Design**：待补充：阶段操作栏、状态转移提示和终止确认。

**Confirmation**：

1. 系统只展示当前状态允许的下一状态和当前用户有权限执行的操作。
2. HR 可以将待筛选推荐为初筛，并可记录终止状态；用人负责人可以处理初筛结果。
3. 用人负责人明确初筛通过后，候选人才能进入待邀约；初筛不通过进入淘汰，待补充保持初筛状态。
4. 候选人同意后才能创建面试并进入面试中。
5. 当前配置的最后一轮面试完成后，候选人才能进入待决策。
6. 录用只能由 HR 确认；淘汰和候选人放弃进入终止状态后不能恢复。
7. 每次状态变更记录前后状态、操作者、时间和备注。

### US-302 记录邀约结果

**Card**：作为 HR负责人或其他 HR成员，我希望记录候选人在招聘平台上的邀约结果，以便决定是否安排面试。

**Conversation**：邀约状态为待邀约、邀约中、同意、拒绝、失联。HRM 不直接发送外部消息；HR负责人或其他有权限的 HR成员负责在招聘平台完成邀约并回填结果，状态变更必须填写备注。

**Design**：待补充：邀约记录抽屉或表单。

**Confirmation**：

1. HR 可以记录邀约状态和备注，备注为空时不能提交状态变更。
2. 只有邀约状态为“同意”的候选人可以进入面试安排。
3. 拒绝或失联可以记录为候选人放弃，并要求填写对应原因或备注。
4. 系统展示最近一次邀约状态、操作人、时间和备注。
5. 系统不向候选人发送消息，也不把 HRM 的状态伪装成招聘平台答复。

## Epic E：面试与评价

### US-401 维护面试轮次模板

**Card**：作为用人负责人，我希望按招聘角色和面试职级维护面试模板，以便不同岗位使用合适的面试流程。

**Conversation**：模板包含轮次名称和顺序、面试角色/职级、默认时长、评价模板和是否必经。没有匹配模板时，用人负责人需要新建或补充配置后才能安排面试。

**Design**：待补充：面试模板列表、模板编辑和轮次排序。

**Confirmation**：

1. 只有用人负责人可以创建和维护其权限范围内的面试模板。
2. 模板可以关联招聘角色和面试职级，并维护至少一轮面试。
3. 每一轮必须有名称、顺序、角色/职级、默认时长、评价模板和是否必经字段。
4. 保存后轮次顺序稳定，不能出现重复顺序。
5. 模板被业务记录使用后，修改不会无痕改变已有面试历史。

### US-402 创建和安排面试

**Card**：作为 HR，我希望创建面试并记录时间，以便面试官知道安排并在 HRM 中完成协作。

**Conversation**：HR成员创建面试，用人负责人指定本轮面试官。面试时间直接记录在 HRM；HRM 不同步飞书日历。面试官可以一次指定多人，也可以在具体轮次临时更换。

**Design**：待补充：面试创建、轮次和面试官选择页面。

**Confirmation**：

1. 非“同意”邀约状态的候选人不能创建面试。
2. 面试必须包含候选人、轮次、面试时间、至少一名面试官和创建人。
3. HR 可以改期，修改后详情和待办展示最新时间，并记录变更历史。
4. 用人负责人可以指定或更换面试官，更换不改变候选人阶段。
5. 公司取消时保留候选人原阶段并记录公司取消原因，不自动重新邀约。
6. 候选人取消时可以记录为候选人放弃，并与公司取消区分。

### US-403 提交结构化面试评价

**Card**：作为面试官，我希望用少量结构化字段提交评价，以便让招聘决策有统一依据。

**Conversation**：评价包含面试结论、少量评价维度、是否推荐、风险项和文字补充。面试官可查看同部门、同职位的其他评价，但不能修改其他人的评价；用人负责人和 HR 可以修改评价，修改需要审计。

**Design**：待补充：评价表单、已提交评价和修改记录。

**Confirmation**：

1. 被指定的面试官可以提交自己负责轮次的评价。
2. 评价至少包含面试结论、评价维度、是否推荐、风险项和文字补充字段。
3. 面试官可以查看符合范围的其他评价，但不能修改或冒用其他面试官身份提交。
4. HR 和用人负责人可以在权限范围内修改评价，修改前后内容和原因写入审计。
5. 评价展示提交人、提交时间、轮次和当前版本。
6. 评价未提交时，相关待评价事项出现在对应工作台。

### US-404 完成面试并做最终决策

**Card**：作为 HR负责人，我希望在最后一轮面试完成后确认录用结果，以便结束候选人的招聘流程。

**Conversation**：最后一轮面试完成后候选人进入待决策。HR负责人或其他有 HR成员角色的授权用户可以完成最终录用确认；HR成员、用人负责人和面试官可以按权限发起淘汰或候选人放弃。

**Design**：待补充：待决策面板和终止确认弹窗。

**Confirmation**：

1. 候选人完成当前配置的最后一轮面试后可以进入待决策。
2. 待决策状态继续出现在长期未推进提醒范围内，直到进入终止状态或录用。
3. 只有 HR 可以将待决策候选人变更为录用。
4. 录用、淘汰和候选人放弃均要求记录操作者和变更时间。
5. 进入录用、淘汰或候选人放弃后，候选人不能再次进入其他阶段。

## Epic F：工作台与提醒

### US-501 使用角色工作台处理待办

**Card**：作为招聘参与人，我希望打开工作台就看到自己的待办，以便减少查找和重复沟通。

**Conversation**：HR 看全局招聘和逾期事项；用人负责人看自己的部门职位和候选人；面试官看自己的面试和待评价。工作台中的快捷操作仍需通过角色和状态校验。

**Design**：待补充：三类角色工作台。

**Confirmation**：

1. HR、用人负责人和面试官登录后看到不同的数据范围和待办内容。
2. 工作台至少展示待评价、逾期面试和长期未推进事项。
3. 用户可以从待办直接进入候选人详情、记录邀约、安排面试、补交评价或处理逾期事项。
4. 快捷操作无权限或不满足状态前置条件时，系统阻止操作并说明原因。
5. 待办数量和状态与候选人、面试和评价的最新记录一致。

### US-502 处理长期未推进提醒

**Card**：作为职位 HR负责人或用人负责人，我希望收到长期未推进提醒，以便及时推动候选人。

**Conversation**：从最后一轮面试结束开始计算，按东八区工作日每 3 个工作日提醒一次，通知职位 HR负责人和用人负责人。每天同一候选人最多提醒一次；状态操作不会重置计算。未参加过面试的候选人不提醒，其他 HR成员可从全局工作台查看但不默认收到提醒。

**Design**：待补充：提醒列表、提醒状态和候选人时间线。

**Confirmation**：

1. 只有完成过至少一轮面试的候选人进入长期未推进计算。
2. 系统从最后一轮面试结束时间开始按东八区工作日计算 3 个工作日周期。
3. 每个周期提醒职位 HR负责人和用人负责人，同一候选人同一天最多产生一条提醒。
4. 候选人处于待决策时仍继续提醒，状态变更不重置起算时间。
5. 候选人进入录用、淘汰或候选人放弃后停止提醒。
6. 公司取消面试不重新邀约，也不重置长期未推进计算。

## Epic G：配置与治理

### US-601 维护业务字典

**Card**：作为管理员，我希望维护业务字典，以便不用修改代码就能调整招聘选项。

**Conversation**：职位类型、工作地点、招聘角色、面试职级、来源渠道、面试结论、推荐结果、风险项、淘汰原因和放弃原因都由字典提供。已被使用的选项只能停用。

**Design**：待补充：字典管理页面。

**Confirmation**：

1. 管理员可以新增、编辑、排序和停用字典选项。
2. 已被业务记录使用的选项不能物理删除，只能停用。
3. 停用选项不能用于新建记录，但历史记录仍显示原名称。
4. 候选人、职位、面试和评价表单只展示对应字典中的启用选项。
5. 字典变更记录操作者、时间、前后值和操作结果。

### US-602 软删除、恢复和审计

**Card**：作为管理员，我希望恢复误删数据并查看不可篡改的审计记录，以便保证招聘数据可追溯。

**Conversation**：职位、候选人、附件引用和招聘过程记录统一软删除。管理员可以恢复；普通业务页面不显示软删除记录。审计记录不可删除或无痕修改。

**Design**：待补充：回收站、恢复确认和审计查询页面。

**Confirmation**：

1. 业务删除只改变记录状态，不直接物理删除主数据或附件引用。
2. 软删除记录从正常列表和搜索结果中隐藏，管理员可在恢复范围内查询。
3. 只有管理员可以恢复软删除记录，恢复必须填写原因。
4. 删除和恢复记录操作者、时间、原因和原记录标识。
5. 审计记录没有删除入口，普通业务用户不能修改历史审计内容。
6. 查看、下载、创建、修改、状态变更、合并、删除和恢复等敏感操作可按用户和时间查询。
