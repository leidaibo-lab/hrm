# 招聘管理测试场景

以下场景用于连接用户故事和 MVP 发布验收。每个场景包含前置条件、角色、动作和可观察结果，具体测试数据由技术设计阶段补充。

## TS-AUTH-001：多角色用户和数据范围

**测试目标**：验证平台管理员、HR成员、用人负责人和面试官的权限边界。

**前置条件**：准备四类用户、两个部门、一个职位、一个候选人和一份简历。

**角色**：系统管理员、HR成员、用人负责人、面试官。

**步骤**：

1. 使用系统管理员访问候选人详情和下载简历。
2. 使用 HR成员访问全公司职位、候选人和简历。
3. 使用其他部门用人负责人访问试点职位和候选人。
4. 使用被指派面试官访问候选人详情并尝试下载简历。

**预期结果**：

- 系统管理员不能仅凭平台权限访问招聘敏感数据。
- HR成员可在权限范围内查看和下载简历。
- 非所属部门用人负责人被阻止访问。
- 面试官可查看授权资料，但一期不能下载简历。
- 每次允许或拒绝访问都有审计记录。

## TS-JOB-001：职位建档、关闭和恢复

**测试目标**：验证职位来源和关闭状态规则。

**前置条件**：准备一个飞书职位发布完成的来源链接和一个未发布职位来源。

**角色**：HR成员。

**步骤**：

1. 使用未发布职位来源尝试创建 HRM 职位。
2. 使用已发布职位来源创建职位并录入必填信息。
3. 将职位调整为已关闭并尝试新增候选人。
4. 恢复职位后再次尝试新增候选人。

**预期结果**：

- 未发布职位不能创建。
- 已发布职位创建成功并保留来源凭证。
- 已关闭职位禁止新增候选人，但已有流程不被删除或终止。
- 恢复后允许新增候选人，关闭、恢复和原因均写入审计。

## TS-CAND-001：候选人导入和简历追溯

**测试目标**：验证简历来源、附件安全和导入信息完整性。

**前置条件**：准备合法 PDF、非法文件类型、缺少联系方式的候选人资料。

**角色**：HR成员。

**步骤**：

1. 导入完整候选人资料和合法简历。
2. 上传非法类型或内容不匹配的文件。
3. 导入缺少联系方式的候选人。
4. 查看候选人详情和审计记录。

**预期结果**：

- 成功记录来源标识、导入人、导入时间和职位关联。
- 非法附件被拒绝，不产生孤立附件记录。
- 缺少联系方式不能保存。
- 查看和下载简历按权限控制并写入审计。

## TS-CAND-002：重复候选人合并

**测试目标**：验证重复判断、合并确认和历史记录保留。

**前置条件**：准备姓名和联系方式完全相同、仅姓名相同、联系方式相同但姓名不同的候选人。

**角色**：HR成员、系统管理员。

**步骤**：

1. 导入三类候选人并触发重复判断。
2. 对强重复执行合并确认。
3. 查看新记录、旧记录、面试记录和合并审计。
4. 使用无权限角色尝试合并。

**预期结果**：

- 完全一致触发强重复提示；仅姓名相同不判重；联系方式相同但姓名不同要求 HR 判断。
- 合并保留合并前后标识、操作者、时间和原因。
- 旧记录被软删除，历史关系可追溯。
- 无权限角色不能合并。

## TS-FLOW-001：候选人阶段正向流转

**测试目标**：验证阶段前置条件、角色责任和不可回退规则。

**前置条件**：候选人处于待筛选，准备 HR、用人负责人和面试官账号。

**角色**：HR成员、用人负责人、面试官。

**步骤**：

1. HR 将候选人推荐到初筛。
2. 用人负责人记录待补充、通过和不通过结果。
3. 在未记录邀约同意时尝试创建面试。
4. 记录邀约同意后创建面试。
5. 尝试将候选人退回上一个阶段。

**预期结果**：

- 待补充保持初筛，不直接进入面试。
- 初筛通过后进入待邀约，不通过进入淘汰。
- 未记录邀约同意不能创建面试。
- 所有状态变更保留前后状态、操作者、时间和备注。
- 已推进阶段不能回退，终止状态不能恢复。

## TS-FLOW-002：邀约结果和面试前置条件

**测试目标**：验证邀约状态记录、备注要求和创建面试的前置条件。

**前置条件**：候选人处于待邀约，准备 HR成员账号和不同邀约结果。

**角色**：HR成员。

**步骤**：

1. 在没有备注的情况下记录邀约中、拒绝或失联。
2. 记录邀约同意但不创建面试。
3. 在邀约状态为同意后创建面试。
4. 查看最近一次邀约状态、操作人、时间和备注。

**预期结果**：

- 邀约状态变更没有备注时不能提交。
- 拒绝或失联可以结束候选人流程，但不能创建面试。
- 只有同意状态允许创建面试。
- 邀约记录和来源不会被伪装成 HRM 自动发送的外部消息。

## TS-INT-001：安排面试时选择角色和职级

**测试目标**：验证招聘角色和面试职级不属于职位必填字段，并用于模板匹配。

**前置条件**：职位没有招聘角色和面试职级字段；准备两个角色/职级组合和对应模板。

**角色**：HR成员、用人负责人。

**步骤**：

1. 创建职位时不填写招聘角色和面试职级。
2. 安排面试时选择招聘角色和面试职级。
3. 修改模板后查看已创建面试。
4. 使用无匹配模板的组合尝试安排面试。

**预期结果**：

- 职位可以在不填写招聘角色和面试职级的情况下创建。
- 安排面试时必须选择角色和职级，并匹配对应模板。
- 已创建面试保留模板和字段快照，不随模板修改而变化。
- 无匹配模板时不能安排面试，并提示补充配置。

## TS-INT-002：面试安排与变更

**测试目标**：验证面试时间、轮次、面试官和取消规则。

**前置条件**：候选人邀约状态为同意，存在可用面试模板。

**角色**：HR成员、用人负责人。

**步骤**：

1. HR 创建面试并填写轮次、时间和至少一名面试官。
2. 用人负责人更换面试官。
3. HR 修改面试时间。
4. 分别记录公司取消和候选人取消。

**预期结果**：

- 面试包含候选人、轮次、时间、面试官和创建人。
- 面试官更换不改变候选人阶段。
- 改期后详情和待办显示新时间，并保留变更历史。
- 公司取消与候选人取消原因分开记录，公司取消不自动重新邀约。

## TS-INT-003：提交结构化面试评价

**测试目标**：验证面试官只能提交自己的评价，且评价修改可审计。

**前置条件**：准备已安排面试、两名面试官和结构化评价字段。

**角色**：面试官、HR成员、用人负责人。

**步骤**：

1. 被指派面试官提交完整评价。
2. 面试官尝试修改其他面试官的评价。
3. HR或用人负责人修改评价并填写修改原因。
4. 查看评价版本和审计记录。

**预期结果**：

- 被指派面试官可以提交自己的评价。
- 面试官不能修改或冒用其他面试官身份提交评价。
- HR和用人负责人只能在权限范围内修改，且前后内容、操作者、时间和原因完整记录。
- 评价展示提交人、提交时间、轮次和当前版本。

## TS-DEC-001：最后一轮评价未提交

**测试目标**：验证未提交评价时候选人保持面试中。

**前置条件**：候选人已完成当前配置的最后一轮面试；该轮有两名被指派面试官，其中一人未提交评价。

**角色**：面试官、HR成员、用人负责人。

**步骤**：

1. 一名面试官提交评价。
2. HR 尝试将候选人推进到待决策。
3. 查看候选人阶段和工作台待办。
4. 第二名面试官提交评价。
5. 再次推进候选人到待决策。

**预期结果**：

- 第一次推进被阻止，候选人仍为面试中。
- 未提交评价继续显示为待评价事项。
- 所有被指派面试官提交评价后，候选人可以进入待决策。
- 推进操作和评价提交均记录审计。

## TS-WORK-001：角色工作台和待办

**测试目标**：验证不同角色看到正确的数据范围和待办，并能进入有权限的快捷操作。

**前置条件**：准备 HR、用人负责人、面试官账号，以及待评价、逾期面试和待决策候选人。

**角色**：HR成员、用人负责人、面试官。

**步骤**：

1. 分别登录三类账号并查看工作台。
2. 从待办进入候选人详情或评价表单。
3. 使用无权限角色尝试执行快捷操作。
4. 完成一项待办后刷新工作台。

**预期结果**：

- HR看到全局招聘范围，用人负责人看到所属部门范围，面试官看到被分配的面试和待评价。
- 待评价、逾期面试和长期未推进事项正确聚合。
- 快捷操作仍通过角色、数据范围和状态前置条件校验。
- 待办数量和状态与最新业务记录一致。

## TS-WORK-002：长期未推进提醒

**测试目标**：验证提醒计算、角色接收人、去重和终止条件。

**前置条件**：准备已完成至少一轮面试且处于待决策的候选人，设置东八区工作日历。

**角色**：系统任务、职位 HR负责人、用人负责人。

**步骤**：

1. 从最后一轮面试完成且评价全部提交的时间开始计算工作日。
2. 到达三个工作日时生成提醒。
3. 同一天重复运行提醒任务。
4. 将候选人改为录用、淘汰或候选人放弃。
5. 再次运行提醒任务。

**预期结果**：

- 只对完成过面试的候选人生成提醒。
- 提醒发送给职位 HR负责人和用人负责人，每个候选人每天最多一条。
- 候选人进入终止状态或录用后停止提醒。
- 提醒计算和生成结果可审计。

## TS-GOV-001：字典停用和历史值

**测试目标**：验证字典选项维护和历史记录稳定性。

**前置条件**：准备一个已被候选人或职位使用的字典选项和一个未使用选项。

**角色**：系统管理员、HR成员。

**步骤**：

1. 管理员尝试删除已使用选项。
2. 管理员停用已使用选项。
3. HR 创建新记录并查看可选项。
4. 查看使用旧选项的历史记录。

**预期结果**：

- 已使用选项不能物理删除，只能停用。
- 停用选项不能用于新记录。
- 历史记录继续展示原名称。
- 字典变更记录操作者、时间、前后值和结果。

## TS-GOV-002：软删除、恢复和审计

**测试目标**：验证敏感数据生命周期过渡政策。

**前置条件**：准备职位、候选人、简历、评价、状态历史和审计记录。

**角色**：HR成员、系统管理员、普通业务用户。

**步骤**：

1. HR 发起候选人删除并填写原因。
2. 普通列表和搜索中查询该候选人。
3. 管理员在恢复范围中查询并尝试恢复。
4. 恢复时填写原因并查看审计。
5. 普通用户尝试删除或修改审计记录。

**预期结果**：

- 删除只产生软删除状态，普通页面隐藏记录，附件不立即物理删除。
- 只有管理员可以恢复，恢复前后状态和原因完整记录。
- 审计记录不能被普通界面删除或无痕修改。
- 正式保留期限未确认前不触发自动清理。

## TS-GOV-003：权限矩阵中的下载和导出隔离

**测试目标**：验证查看、下载和导出是独立权限。

**前置条件**：准备 HR成员、用人负责人、面试官和系统管理员账号及一份简历。

**角色**：四类用户。

**步骤**：

1. 各角色查看授权范围内的候选人资料。
2. 各角色尝试下载简历。
3. 各角色尝试批量导出。
4. 查看允许和拒绝操作的审计记录。

**预期结果**：

- 查看权限不自动带来下载权限。
- 一期只有有明确权限的 HR成员可以下载简历。
- 一期所有角色批量导出均被阻止。
- 允许、拒绝和失败原因均写入审计且不泄露敏感信息。
