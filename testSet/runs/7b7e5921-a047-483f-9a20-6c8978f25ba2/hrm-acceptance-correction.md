# HRM 招聘首期验收补正

归属 Run：`7b7e5921-a047-483f-9a20-6c8978f25ba2`。本文件修正 fixture 固定样例测试计划，正式执行前须先完成产品稿 Q1–Q5 的人工确认。

## 用例

| 用例 | 场景 | 预期 |
| --- | --- | --- |
| HRM-01 | 打开预置职位候选人列表 | 显示候选人、初筛状态、邀约状态、待处理标签和最近处理信息 |
| HRM-02 | 初筛通过并保存 | 列表与详情同步显示“通过”，记录处理人和时间 |
| HRM-03 | 初筛淘汰且未填写原因 | 提交被拒绝，已有结果不改变 |
| HRM-04 | 初筛淘汰后直接写入邀约 | 服务端拒绝越权状态转换；不产生邀约结果 |
| HRM-05 | 初筛通过后记录邀约接受/拒绝/未响应 | 详情和列表显示一致的邀约结果 |
| HRM-06 | 刷新页面 | 按 Q5 的确认结果保留或清除；不得出现前后端不一致 |
| HRM-07 | 访问面试安排能力 | 本期无可用入口，或明确提示未支持；不得创建面试数据 |
| HRM-08 | HR 与用人负责人切换模拟标签 | 仅展示已授权的本地模拟范围，不声称真实认证 |

## 证据边界

本 Run 的 fixture 固定检查只能证明 Workflow 门禁、归档和本地回执链路可运行，不能证明以上 HRM 业务断言已执行通过；真实业务检查需在确认 Q1–Q5 后登记并运行。
