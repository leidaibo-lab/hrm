# HRM 招聘协作项目需求文档

**作者：** 产品写作角色  
**状态：** 草案，待业务选择补齐  
**适用范围：** 项目总览、招聘管理、招聘工作台及验收配套  
**依据：** 当前业务简述、已读取的原始材料及人工答复 Q1–Q18  
**说明：** 本文整理已确认需求；未决选择和建议另行标明，不代表已批准。

## 1. 项目总览

### 1.1 背景与目标

公司招聘信息分散在候选人资料、飞书云盘及零散消息中，HR 与用人团队需要反复确认候选人进度、责任人和下一步。项目希望提供统一的招聘协作平台，降低信息交流成本并减少候选人长期未推进的问题。前端团队的全栈实践是独立学习目标，不替代业务成效验收。

招聘申请、审批和职位发布继续在飞书完成；HRM 从职位发布后承接内部招聘协作。本期按人工录入和模拟角色体验设计，不依赖飞书、Boss 直聘接口或外部消息自动化。

### 1.2 用户与价值

| 用户群体 | 要完成的工作 | 当前困难与期望价值 |
|---|---|---|
| 负责 HR | 录入候选人、筛选推荐、联系候选人、安排面试、跟进录用及到岗 | 希望集中维护进度、沟通记录与下一步，减少反复询问 |
| 用人负责人 | 初筛候选人、决定是否进入下一轮、作招聘评估决定 | 希望查看本职位候选人资料与评价，并明确招聘责任和当前进度 |
| 面试官 | 参加被安排的面试并提交个人评价 | 希望只看到本人面试所需资料和自己的评价任务 |
| 管理员 | 维护模拟人员、角色和职位责任分配 | 希望维护协作配置，但不因此默认获得招聘业务资料访问权或决定权 |

**价值主张（六要素）：**

- **谁：** 参与招聘协作的 HR、用人负责人和面试官。
- **为什么：** 需要共同推进候选人，并明确责任、结果和下一步。
- **之前：** 资料分散，依赖飞书云盘及零散消息传递进展。
- **如何：** HRM 集中维护候选人应聘记录、面试评价、处理结果和待办。
- **之后：** 招聘参与者可根据职位责任查看所需信息，识别未完成工作和等待事项。
- **替代方案：** 继续使用分散资料与消息；本项目提供集中协作，但不替换飞书审批和职位发布。

### 1.3 目标与衡量

本期目标是验证招聘协作流程、责任交接、访问范围和待办是否按规则工作。使用合成数据无法证明真实招聘停滞或沟通成本已改善。

未来真实试点可观察候选人停滞、评价提交情况及跨角色信息确认成本；目前没有基线、统计口径或目标值，不设提升比例、完成期限或“逾期率”目标。

## 2. 范围与边界

### 2.1 本期承接的招聘流程

职位发布后的内部招聘协作：候选人录入与 HR 筛选推荐、用人负责人初筛、外部邀约记录、按需安排多轮面试、同轮多人独立评价、招聘评估，以及 HR 后续沟通和实际到岗确认。

本期采用预置或录入的合成职位与候选人资料，以及模拟人员和角色。不录入真实简历、联系方式、薪资或其他真实候选人资料，不建设真实认证。

### 2.2 明确边界

| 事项 | 处理方式 |
|---|---|
| 招聘需求申请、审批、职位发布 | 保留在飞书，不在 HRM 重建审批流 |
| 候选人与招聘协作信息 | 在 HRM 人工维护；本期不依赖飞书或 Boss 直聘接口 |
| 外部沟通 | 由 HR 记录结果；不依赖外部消息自动化 |
| 招聘成功结束 | HR 与候选人后续沟通并确认实际到岗入职后结束 |
| 完整 Offer、入职手续、员工档案、薪酬管理 | 未获得纳入本期的明确确认，不据到岗节点扩建 |
| 绩效管理、通用人资工作台 | 是否正式延期仍待确认，不写成已批准的排除项 |
| 真实资料试点 | 不在本期合成数据及模拟身份范围内 |

### 2.3 用户故事

**候选人进度交接。** 作为负责 HR，我希望集中记录候选人应聘进展、当前责任和下一步，以便与用人团队交接时不必拼接零散消息。

**面试评价与推进。** 作为用人负责人，我希望看到同轮面试官分别提交的评价，并在评价齐全后决定是否进入下一轮，以便按完整材料推进招聘；必要时仍可提前作最终招聘评估决定。

**工作待办。** 作为招聘参与者，我希望看到与自己责任相关的待办、最近推进时间和等待事项，以便识别尚未完成的工作，而不是依赖未定义的超时天数。

## 3. 已确认的业务规则

### 3.1 角色与权限

每个职位明确一名负责 HR 和一名用人负责人。人员、模拟账号、系统角色及职位上的具体责任应区分表达；兼任时如何合并权限尚未确定。

| 角色 | 已确认职责 | 已确认可见范围 |
|---|---|---|
| 负责 HR | 资料维护、筛选推荐、外部沟通、面试安排与异常处理、薪资沟通和录用推进、到岗确认；可主动终止推进并填写原因 | 可看本职位资料与评价 |
| 用人负责人 | 决定初筛结果、下一轮推进及招聘评估通过或不通过 | 可看本职位资料与评价 |
| 面试官 | 对本人被安排的面试提交个人评价 | 仅看本人被安排候选人的必要资料和本人评价 |
| 管理员 | 维护模拟人员、角色及职位责任分配；职位责任变更时转交未完成协作待办 | 不默认查看简历或评价，不默认拥有招聘评估决定权 |

面试官更换需要调整面试安排；已提交评价保留原作者，不改署名。管理员的配置权限不等于业务资料访问权。

### 3.2 应聘对象、进度与结束

- 同一候选人最多有一个进行中的应聘职位；识别重复候选人的依据和冲突处理尚未确认。
- 应聘结束后不直接恢复；再次应聘应建立新记录。误操作纠错规则另待确认，不能通过普通恢复绕过此限制。
- 面试评估通过、薪资谈妥或承诺到岗均不代表成功结束；HR 确认实际到岗入职后才确认成功结束。
- 初筛或评估不通过、候选人明确退出，以及适用阶段的薪资未达成、录用取消或确认不再到岗，均可结束应聘。
- HR 可决定公司主动终止招聘或撤回录用推进，填写原因并结束推进；此权力不允许 HR 改写用人负责人的专业评估结论。
- 等待到岗期间是否正式占用唯一进行中应聘名额，尚未单独确认；当前不能将该解释写成已确认规则。

### 3.3 面试、评价与异常

- 外部邀约后，暂未联系上由 HR 继续跟进；明确拒绝可结束应聘。
- 只有与候选人约定明确时间后才可安排面试。
- 面试按需逐轮安排；同轮可有多名面试官，须分别提交评价。
- 正常进入下一轮前，必须收齐本轮全部面试官评价。
- 用人负责人仍可提前作最终招聘评估决定，并关闭未完成的评价任务、保留记录。该例外不允许缺评时正常进入下一轮。
- HR 处理改期、取消和未到场，保留原安排及原因。候选人仍有意愿时重新约定时间；明确退出才结束应聘。
- 未实际发生的面试不要求提交评价。取消旧安排时关闭旧安排的待办并保留历史；重新安排产生对应的新待办。一次未到场或面试取消不自动淘汰。

## 4. 模块需求

### 4.1 招聘管理

| 能力 | 需求与验收依据 |
|---|---|
| 候选人录入与推荐 | HR 可为已发布职位人工维护合成候选人资料并提交推荐；具体必填字段、HR 不推荐路径及重复识别规则待确认 |
| 初筛与邀约 | 用人负责人决定初筛结果；通过后由 HR 跟进邀约。明确时间是安排面试的前提 |
| 面试安排 | 按需逐轮安排；同轮可安排多名面试官并分别形成评价任务。面试完成的登记方式尚未确认 |
| 评价 | 每位面试官提交个人评价；正常进入下一轮前须本轮评价齐全。评价修改规则尚未确认 |
| 最终评估 | 用人负责人决定评估通过或不通过；允许提前决定并关闭未完成评价任务，保留历史 |
| 后续推进与到岗 | HR 负责薪资沟通、录用推进和到岗确认；实际到岗后成功结束。薪资金额是否记录、到岗所需字段待确认 |
| 失败与中止 | 支持已确认的失败或中止结果；HR 可主动终止并填写原因。其他原因的具体记录要求待细化 |
| 责任变更 | 管理员调整职位责任时，未完成协作待办转交，已提交评价保留原作者；旧责任人撤权时点等细则待确认 |

### 4.2 招聘工作台

工作台服务已确认的招聘流程，不据此扩展为绩效或通用人资工作台。至少要区分以下三类待办或提示：

1. 面试时间已过，但尚未登记面试结果。
2. 面试已完成，但评价未提交。
3. 候选人长期没有实质推进记录。

Q18 的“按照建议执行”确认了提示方向：期限未知时先展示待办、最近推进时间和等待事项；**未确认超时天数、自然日或工作日算法、等待期豁免，也不承诺自动判定逾期或自动催办。**待办生成、转交、完成和关闭的完整规则仍待细化。

## 5. 验收配套

以下是设计验收的业务场景，不代表已执行测试。资料和身份均应使用合成数据与模拟角色。

| 编号 | 场景 | 可观察的预期结果 |
|---|---|---|
| A1 | 初筛决定 | 用人负责人可提交通过或不通过；通过进入邀约，不通过可结束。HR 后续操作不能改写专业评估结论 |
| A2 | 面试时间边界 | 未约定明确时间不能完成面试安排；已约定明确时间可安排。联系不上仍由 HR 跟进，不自动结束 |
| A3 | 正常进入下一轮 | 同轮有两名面试官且仅一人提交评价时，不允许正常进入下一轮；收齐两人评价后，缺评条件解除 |
| A4 | 提前最终决定 | 评价未齐时，用人负责人可提前作最终评估决定；未完成评价任务关闭且保留记录，但不得伪装成已提交或借此进入下一轮 |
| A5 | 面试异常 | HR 处理改期、取消或未到场并记录原因；仍有意愿时重新约定。原安排历史保留，旧待办关闭，新安排产生相应待办；未发生面试不要求评价 |
| A6 | 评估通过后的后续 | 薪资达成一致或承诺到岗不能成功结束；HR 确认实际到岗入职后才成功结束 |
| A7 | 主动终止 | HR 不填写原因不能完成主动终止；填写原因后可结束推进，原招聘评估结论仍保持原义 |
| A8 | 同一候选人应聘 | 已知同一候选人有进行中应聘时，不允许再建立另一进行中职位应聘；已结束后再次应聘建立新记录，不直接恢复原记录 |
| A9 | 可见性 | HR 和用人负责人可看本职位资料与评价；面试官只能看本人被安排候选人的必要资料和本人评价；管理员不因配置权限默认取得简历、评价或评估决定权 |
| A10 | 责任变更 | 职位责任变更时未完成协作待办转交；已提交评价保留原作者；面试官更换通过调整安排处理 |
| A11 | 无阈值工作台 | 可查看待办、最近推进时间和等待事项；未配置期限时不能以任意天数标为逾期 |
| A12 | 数据边界 | 本期体验数据仅为合成资料和模拟身份；不出现真实候选人简历、联系方式或薪资资料 |

完整的字段校验、失败提示、写入失败后的数据影响、并发操作和所有访问入口尚无足够业务规则，暂不能形成相应验收标准。验收设计不替代对这些行为的确认。

## 8. 决策与讨论记录

本节记录需求形成过程中的取舍，**不是正式需求条款**。仅明确标记为“已确认”的选择进入上文需求基线。

| 主题 | 已确认的选择与影响 |
|---|---|
| 首期招聘范围（Q1） | 从原材料的“到邀约为止”扩展为包含多轮面试、评价与最终招聘评估；暂不因此加入完整 Offer 或入职管理 |
| 数据与身份（Q2） | 仅合成数据和模拟角色；不录入真实候选人资料，不建设真实认证 |
| 责任链（Q3） | 采用负责 HR、用人负责人、面试官和管理员的职责区分；每个职位明确负责 HR 与用人负责人 |
| 并行应聘（Q4） | 同一候选人最多一个进行中的应聘职位 |
| 成效方向（Q5） | 聚焦减少招聘停滞、降低 HR 与用人团队信息交流成本并提供统一协作平台；没有基线，不设改善比例 |
