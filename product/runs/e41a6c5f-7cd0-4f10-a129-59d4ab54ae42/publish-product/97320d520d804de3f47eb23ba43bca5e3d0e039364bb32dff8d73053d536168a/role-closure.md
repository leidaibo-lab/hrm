**三、规则已足够明确的分段验收场景**

以下场景给出可确定的业务预期。可通过预置合成状态分别验证；具体页面操作、提示文案及准备这些状态的完整业务路径，仍需后续PRD补齐。

统一准备：合成职位J1、J2；负责HR H、用人负责人L；面试官I1、I2；管理员A。所有操作使用模拟身份。

| 编号／类型 | 前置条件、角色及操作 | 可检查预期 |
|---|---|---|
| T01 正常／权限 | H已推荐J1候选人；L提交初筛通过或不通过 | L具有初筛决定权；通过可进入邀约，不通过可结束。H不能借后续推进改写L的专业结论 |
| T02 边界 | 初筛通过；H分别在“尚无明确时间”和“已约定明确时间”下尝试安排面试 | 无明确时间不能完成面试安排；有明确时间可安排。联系不上仍由HR跟进，不等于应聘结束 |
| T03 正常／边界 | 一轮有I1、I2；先预置仅I1已提交，再预置两人均已提交；L尝试正常进入下一轮 | 缺任一评价时不能正常进入下一轮；收齐后不再被“缺评”条件阻止。每人评价分别保存 |
| T04 例外 | 本轮仍缺I2评价；L作提前最终评估决定 | 允许最终决定；未完成评价任务结束并保留记录；不能借此生成“正常进入下一轮”的结果 |
| T05 异常 | 尚未发生的面试；H依次处理改期、取消、未到场且仍愿继续，以及明确退出 | 前三类不自动结束应聘；原安排和原因保留；未发生面试不要求评价；旧安排待办关闭，重排后产生对应待办。明确退出可结束应聘 |
| T06 正常／边界 | 已评估通过；H依次记录薪资达成一致、承诺到岗、确认实际到岗 | 前两项不能作为成功结束依据；HR确认实际到岗入职后才确认成功结束 |
| T07 异常／权限 | 已有L的评估结论；H尝试主动终止，分别不填写、填写原因 | 不填原因不能完成该操作；填写原因后可结束推进；原评估结论保持原义，不被改写成“不通过” |
| T08 边界 | 已明确为同一候选人且J1应聘进行中，尝试新增J2进行中应聘；再以已结束记录验证再次应聘 | 不允许同时存在两个进行中职位；结束后再次应聘创建新记录，不能普通恢复原记录。不同资料是否同一人另待去重规则 |
| T09 权限 | H、L、I1、A分别访问本职位资料、未安排给I1的候选人、I2评价 | H、L可看本职位资料及评价；I1仅看本人被安排候选人的必要资料和本人评价；A不因管理员身份取得简历、评价或招聘决定权 |
| T10 责任变更 | 职位有未完成协作待办及I1已提交评价；A变更职位责任人，再更换面试官安排 | 未完成协作待办转交；已提交评价作者保持I1；面试官更换通过调整安排处理，不能改署名 |
| T11 工作台边界 | 预置若干未完成待办及已记录的推进时间、等待事项；模拟责任人查看 | 能看到对应待办、最近推进时间和等待事项；未配置期限时，不以任意天数自动标逾期。具体时间刷新规则另待确认 |
| T12 数据边界 | 检查演示数据、附件、身份和验收准备材料 | 仅使用合成资料和模拟身份；不出现真实候选人简历、联系方式、薪资。该检查不能证明系统能自动识别全部真实资料 |

T09还应覆盖所有实际提供的访问和写入入口，包括绕过页面直接发起操作的情况。具体拒绝反馈、拒绝后是否存在残留写入，需在下表确认后纳入完整异常验收。

“被关闭评价任务不计为已提交评价”是必要的统计区分建议，尚不能把它包装成已确认统计规则；当前至少必须保留任务关闭事实，避免丢失历史。

**四、待补验收及阻塞项**

| 编号 | 尚缺的业务决定 | 不能确定的验收结果／建议处理 |
|---|---|---|
| B1 面试完成认定 | 谁登记实际完成；未登记完成能否提交评价；信息冲突如何处理 | 无法确定评价待办生成起点。建议先确定实际发生的认定方式，再定义待办 |
| B2 有效评价集合 | 部分人已评价后改期、取消或换面试官，哪些评价仍有效 | 无法确定“本轮全部收齐”的分母；这直接阻塞跨轮规则的异常验收 |
| B3 修改与纠错 | 评价能否修改；误判不通过、误确认到岗如何更正 | 无法确定修改历史、结果更正及对其他应聘的影响。继续保留“不直接恢复”，不得用普通编辑绕过 |
| B4 候选人识别 | 重复识别依据、重复录入处置；等待到岗是否明确继续占用名额 | 无法验收不同录入入口的一致性。等待到岗占用名额与现有终点相容，建议正式明确 |
| B5 责任与权限 | 旧责任人何时撤权、无人接任怎么办、兼任如何合并权限 | 无法完整验收责任交接和历史访问。建议明确交接前后责任与访问快照 |
| B6 待办生命周期 | 每类待办生成、转交、完成、取消条件；“实质推进”事件；应聘结束时关闭哪些待办 | 无法保证结束后不继续催办、资料编辑不虚假刷新推进时间 |
| B7 字段及敏感信息 | 必要资料、评价内容、结束原因、到岗依据、薪资金额、附件与删除保留规则 | 无法制定必填、空值、格式、修改与可见范围验收；不自行设长度或保留期限 |
| B8 范围与失败影响 | 招聘工作台及其他模块边界；写入失败、重复提交、并发决定、越权拒绝的处理 | 建议失败不改变原状态、不产生重复记录或待办，并说明原因；尚需逐操作确认，不能视为已定规则 |

B1—B5优先影响主流程正确性。B6—B8需要在字段、页面和异常设计阶段补齐，之后才能形成端到端验收附件。自动逾期判断可继续延期；若要求本期加入，则计时起点、阈值、自然日或工作日、等待期豁免立即成为阻塞项。

**五、承重假设挑战与最便宜的检验**

以下按影响、现有不确定性和检验成本作定性排序，未编造概率或量化评分。停止标准均为建议，供人工取舍，不代表发布审批结论。

| 顺序／承重主张 | 最强支持与失败条件 | 最便宜检验及停止标准 |
|---|---|---|
| 1. 各角色能对同一应聘理解相同的进度、责任与结果 | 支持：专业评估、HR推进和成功结束已分权。**失败条件：**同一条“评估通过但未到岗”记录，被不同角色判断为不同的结束状态或无人负责 | 用“通过待到岗、明确退出、HR主动终止、已到岗”四张合成案例卡，请业务方独立标记责任、下一步及结束结果。若结果不一致，暂停冻结状态和待办规则，先补语义 |
| 2. 多人评价规则能同时保证完整性和推进例外 | 支持：正常跨轮收齐、提前最终决定两条路径已明确。**失败条件：**取消或换人后仍无法判断本轮缺谁，或提前决定被用来缺评进入下一轮 | 走查两名面试官、缺一份评价、换人和取消安排案例。若不能唯一确定有效评价集合，暂停冻结跨轮异常规则，先解决B2 |
| 3. 责任转交后工作继续且访问边界仍成立 | 支持：未完成待办转交、评价原作者保留、管理员无默认资料权已确认。**失败条件：**出现无人承接、旧人持续访问或管理员通过配置获得业务权限 | 用一条进行中应聘做交接前后角色访问与待办对照。若存在无责任人或额外访问，暂停完成交接能力验收，补齐撤权和接任规则 |
| 4. 集中平台能减少真实沟通和停滞 | 支持：原始痛点明确，无接口方案也能集中信息。**失败条件：**关键进展仍只留在外部消息中，平台中的责任和下一步无法用于交接 | 当前先用合成案例做跨角色交接走查；未来真实试点再采集现状和使用后证据。若必须回到零散消息才能完成交接，调整记录和交接方式；当前不宣称业务改善已实现 |

现有方案中，保留飞书审批和发布、人工录入、采用无阈值待办，都有清楚的减依赖理由，无需为闭环新增集成或自动催办。无法判断的仍是真实使用频率、维护负担、沟通成本变化及停滞改善；合成演示不能补足这些证据。
