# HRM 招聘协作项目需求文档

**作者：** 产品写作角色  
**状态：** 修订草案，部分业务选择待人工确认  
**适用范围：** 项目总览、招聘管理、招聘工作台、通用工作台入口及验收配套  
**修订依据：** 原稿所载 Q1–Q18 已确认规则、本轮 16 项显式人工答复及所选方案引用的共用规则。  
**说明：** 本文为完整修订稿；验收条目是预期行为设计，不代表已执行测试或取得发布批准。

## 1. 项目总览

### 1.1 背景与目标

招聘信息分散在候选人资料、飞书云盘及零散消息中，HR 与用人团队需要反复确认候选人进度、责任人和下一步。本项目提供统一招聘协作平台，降低信息交流成本，减少候选人长期未推进的问题。前端团队的全栈实践是独立学习目标，不替代业务成效验收。

招聘申请、审批和职位发布继续在飞书完成；HRM 从职位发布后承接内部招聘协作。本期采用人工录入与模拟角色体验，不依赖飞书、Boss 直聘接口或外部消息自动化。

### 1.2 用户与价值

| 用户群体 | 要完成的工作 | 期望价值 |
|---|---|---|
| 负责 HR | 维护资料、筛选推荐、外部沟通、安排面试、处理异常、跟进录用及到岗 | 集中维护进度、沟通记录和下一步，减少反复询问 |
| 用人负责人 | 初筛、决定下一轮、作最终招聘评估 | 查看本职位资料与评价，依据完整材料作决定 |
| 面试官 | 参加本人被安排的面试并提交个人评价 | 获取必要资料，明确个人评价任务 |
| 管理员 | 维护模拟人员、角色、职位责任，核实合并重复档案 | 维护协作配置和交接，不因管理员身份扩大业务权限 |

| 价值要素 | 说明 |
|---|---|
| 谁 | 参与招聘协作的 HR、用人负责人和面试官 |
| 为什么 | 需要共同推进候选人，明确责任、结果及下一步 |
| 之前 | 依赖分散资料与零散消息传递进展 |
| 如何 | 集中维护应聘、面试、评价、结果及待办，按责任提供访问权限 |
| 之后 | 各角色可识别本人工作、等待事项及最近实质推进时间 |
| 替代方案 | 继续使用分散资料与消息；HRM 保留飞书审批和职位发布的现有分工 |

### 1.3 目标与衡量

本期验证合成数据和模拟角色下的流程推进、责任交接、访问边界、数据约束及待办表现。合成数据不能证明真实招聘停滞或沟通成本已改善。

未来真实试点可观察候选人停滞、评价提交情况及跨角色信息确认成本。目前没有基线、统计口径或目标值，不设置改善比例、完成期限或逾期率目标。

## 2. 范围与边界

### 2.1 本期范围

本期包括招聘管理、招聘工作台，以及**仅展示招聘待办的通用工作台入口**；新增入口纳入验收。绩效和其他人资业务延期。（D1）

招聘协作覆盖：候选人录入、HR 筛选推荐、负责人初筛、外部邀约记录、多轮面试、同轮多人独立评价、最终招聘评估、HR 后续沟通及实际到岗确认。

| 事项 | 本期边界 |
|---|---|
| 数据与身份 | 使用预置或录入的合成职位、候选人资料和模拟人员、角色；不建设真实认证 |
| 真实资料 | 不录入真实简历、联系方式、薪资或其他真实候选人资料 |
| 申请、审批、职位发布 | 继续由飞书承担，不重建审批流 |
| 外部沟通 | HR 人工记录结果，不依赖接口或自动发消息 |
| 成功结束 | HR 确认实际到岗入职后才成功结束 |
| Offer、入职手续、员工档案、薪酬管理 | 未确认纳入，不因存在到岗节点而扩建 |
| 真实业务试点 | 另行确认范围及资料治理要求，不属于本期模拟体验 |

### 2.2 用户故事

| 场景 | 用户故事 |
|---|---|
| 进度交接 | 作为负责 HR，我希望集中记录进展、责任和下一步，以便与用人团队交接 |
| 评价与推进 | 作为用人负责人，我希望查看各面试官独立评价，在评价齐全后决定下一轮，必要时提前作最终评估 |
| 工作入口 | 作为招聘参与者，我希望从招聘工作台或通用工作台入口查看招聘待办、最近推进时间及等待事项 |
| 配置交接 | 作为管理员，我希望责任、待办及旧责任授权同时交接，失败时保持原状，以免责任断档 |

## 3. 已确认的业务规则

### 3.1 角色、权限与责任交接

每个职位明确一名负责 HR 和一名用人负责人。人员、模拟账号、系统角色与职位责任应区分表达。

| 角色 | 职责及访问范围 |
|---|---|
| 负责 HR | 维护本职位资料、筛选推荐、外部沟通、面试安排与异常处理、完成登记、后续沟通、到岗确认；可查看本职位资料与评价 |
| 用人负责人 | 决定初筛、正常下一轮推进及最终评估通过或不通过；可查看本职位资料与评价 |
| 面试官 | 查看本人被安排候选人的显示名、应聘职位、合成经历摘要、本人安排及本人评价；不查看其他面试官评价和后续薪资沟通资料 |
| 管理员 | 维护模拟人员、角色、职位责任；核实合并误建重复档案并留痕；不默认查看简历、评价或拥有招聘评估决定权 |

允许同一人兼任角色，按具体职位及面试安排合并合法权限，记录操作所用责任身份。管理员身份不扩权；失去一项责任后，其他有效授权继续保留。（D10）

职位交接必须选定有效接任人；新责任、未完成待办转交、旧责任授权撤销一起生效。无人接任或交接失败时，全部保持原状并提示失败，保留历史。（D9）

面试官更换通过调整个人安排处理，受第 3.3 节有效评价规则约束；已提交评价保留原作者。

### 3.2 候选人、应聘名额与结束

| 主题 | 已确认规则 |
|---|---|
| 候选人识别 | 合成手机号必填，规范化后唯一；格式为 11 位数字且首位为 1。重复手机号复用档案，同名仅提示；误建重复档案由管理员核实合并并留痕（D7） |
| 名额约束 | 同一候选人最多有一个占用名额的应聘；未结束记录的等待到岗例外按下一行处理（D8 更新原并行应聘规则） |
| 等待到岗例外 | HR 记录已约定到岗日期后，该应聘仍未结束，但不占名额，可另开一个占名额应聘；等待到岗记录再度推进前，必须先释放其他占用（D8） |
| 再次应聘 | 已结束应聘不直接恢复；继续招聘或再次应聘必须新建记录 |
| 成功结束 | 评估通过、薪资谈妥、承诺到岗均不代表成功；HR 确认实际到岗入职后才成功结束 |
| 失败或中止 | 初筛或评估不通过、候选人明确退出，以及适用阶段的薪资未达成、录用取消、确认不再到岗，均可结束应聘 |
| HR 主动终止 | HR 可决定公司主动终止招聘或撤回录用推进，必须填写原因；不得改写负责人的专业评估结论 |
| HR 首次筛选不合格 | 人工明确可直接标记“不合格”；是否直接结束、原因是否必填与所选方案存在歧义，见 U1，不据此形成完整结束验收 |

手机号规范化的具体转换规则、等待到岗“再度推进”的事件范围仍待确认，见第 7 节。

### 3.3 面试、评价与异常

| 环节 | 已确认规则 |
|---|---|
| 邀约 | 暂未联系上由 HR 继续跟进；明确拒绝可结束。只有约定明确时间后才能安排面试 |
| 轮次 | 按需逐轮安排，同轮可有多名面试官，分别提交评价 |
| 完成登记 | HR 登记已完成后才能提交评价；此前面试官可保存草稿（D3） |
| 完成状态冲突 | 完成与取消、未到场冲突时阻止覆盖，由 HR 核实更正并留痕（D3） |
| 正常下一轮 | 必须收齐本轮全部有效面试官评价，才可正常进入下一轮 |
| 提前最终评估 | 用人负责人可在缺评时提前作最终评估，关闭未完成评价任务并保留记录；不能借此缺评进入下一轮 |
| 改期、取消、未到场 | HR 处理并保留原安排与原因；仍有意愿时重新约定时间，明确退出才结束；一次取消或未到场不自动淘汰 |
| 未发生面试 | 不要求评价；取消旧安排关闭其待办并保留历史，新安排生成对应新待办 |
| 部分评价已提交后的调整 | 不再修改整轮安排；仅取消未发生的个人安排或更换未评价人员。已发生者评价继续有效，替换者另评，已发生但未评者仍须补交（D4） |
| 评价修改 | 提交后不修改原评价；原作者可追加说明并留存时间，原结论保留；HR、负责人和管理员均不能代改或改署名（D5） |

HR 作为最后一轮面试官时，个人评价遵守上述规则；本轮自定义答复“以 A 为主”的具体含义未明确，不能据此新增决定权或结束规则。

### 3.4 结果纠错

原授权角色填写原因后，可作废错误结果并保留原值：HR 作废误到岗结果，用人负责人作废误评估结果。已结束应聘作废结果后仍保持结束，继续招聘须新建；未结束应聘同步重算待办。（D6）

该纠错权不允许 HR 作废负责人的评估，也不允许负责人代作废 HR 到岗记录。纠错后未结束应聘回到哪个有效阶段、如何处理已关闭任务，仍需明确，见 U4。

## 4. 模块需求

### 4.1 招聘管理

| 能力 | 功能要求 |
|---|---|
| 资料与档案 | HR 人工维护合成资料；手机号重复复用档案；支持管理员核实合并误建重复档案并留痕 |
| 筛选推荐 | 推荐后产生负责人初筛待办；HR 首次筛选不合格的结束路径待 U1 确认 |
| 初筛邀约 | 负责人提交初筛结果；通过后产生 HR 邀约待办，不通过可结束 |
| 面试与评价 | 安排、个人任务、HR 完成登记、草稿、独立提交、有效评价集合及异常调整遵守第 3.3 节 |
| 最终评估 | 用人负责人作通过或不通过决定，支持提前最终评估 |
| 后续及到岗 | HR 维护沟通、薪资状态、预计及实际到岗记录；实际到岗后成功结束 |
| 交接与纠错 | 遵守责任同步交接、角色权限及原授权角色纠错规则 |
| 附件 | 附件与当前流程绑定；暂不允许删除、过期。具体绑定对象及其他历史资料保留规则待确认（D14） |

### 4.2 字段与可见范围

D2、D12 显式选择了共用字段方案，采用下表；D7 的合成手机号必填要求优先于共用方案中联系方式选填的表述。

| 对象 | 字段及校验 | 可见范围或说明 |
|---|---|---|
| 候选人 | 显示名必填，去首尾空白后 1–50 个 Unicode 码点；合成手机号按第 3.2 节必填；其他联系方式选填且只能为合成内容 | 负责 HR、负责人可见本职位资料；面试官不见联系方式 |
| 应聘关联 | 职位、负责 HR 必填；每职位须明确用人负责人 | 按具体职位责任授权 |
| 合成经历摘要 | 作为面试官可见的必要资料；必填性及长度未确认 | 面试官仅在本人被安排的候选人范围可见 |
| 沟通记录 | 沟通日期、结论、下一步、预计到岗日期；尚未预计到岗时日期允许为空 | 负责 HR、负责人可见，面试官不可见（D2） |
| 薪资状态 | 仅记录“达成／未达成／待沟通”，不记录金额 | 负责 HR、负责人可见，面试官不可见（D2） |
| 到岗确认 | 实际到岗日期、确认说明必填；日期采用年月日，实际到岗日期不得晚于登记当天 | 由 HR 确认；负责 HR、负责人可见 |
| 提交评价 | 结论必选“通过／不通过／待讨论”；评价说明必填，1–2000 个 Unicode 码点 | 按第 3.1 节授权；草稿是否允许缺项待确认 |
| 结束原因 | 必填，1–500 个 Unicode 码点 | HR 首次筛选不合格的原因要求受 U1 影响 |
| 留痕 | 责任身份、评价作者、追加说明时间、纠错原因及原值、安排异常原因、交接及合并历史 | 留痕查看权限、完整字段和非附件历史保留期限待确认 |

已明确长度的字段按 Unicode 码点计数；未明确字段不自行补设长度或默认值。

### 4.3 招聘工作台与通用入口

通用工作台入口仅展示招聘待办；招聘工作台提供招聘协作信息。两处均按当前合法权限展示。

| 事件 | 待办生命周期（D11 引用的共用方案） |
|---|---|
| HR 推荐 | 产生负责人初筛待办 |
| 初筛通过 | 产生 HR 邀约待办 |
| 有效面试安排 | 产生面试登记待办 |
| HR 登记实际完成 | 产生个人评价待办 |
| 本轮有效评价齐全 | 产生负责人推进待办 |
| 最终评估通过 | 产生 HR 后续跟进待办 |
| 对应处理成功 | 完成相应待办 |
| 职位责任变更 | 未完成待办随责任一起转交 |
| 取消安排、重新安排 | 关闭旧安排待办；新安排另建 |
| 提前最终评估 | 关闭未完成评价待办并保留记录 |
| 应聘结束 | 关闭该应聘全部未完成待办 |

最近实质推进时间仅由初筛、实际完成登记、评价、推进决定、到岗／结束更新；邀约沟通和安排变化另显示为联系时间，不更新最近推进时间。（D11）

至少区分面试时间已过但结果未登记、面试已完成但评价未提交两类待办，并提供最近推进时间及等待事项，帮助识别长期未推进的候选人。未确认超时天数、自然日或工作日算法、等待豁免，不自动判定逾期或承诺自动催办。

### 4.4 所有操作入口的业务一致性

| 情况 | 必须呈现的结果（D15、D16） |
|---|---|
| 越权 | 拒绝操作且不改变数据 |
| 校验失败、已知写入失败 | 整次业务操作不生效，不留下部分业务结果 |
| 操作结果未知 | 显示待核实，先查询再重试；不直接认定失败或成功 |
| 同次提交重复送达 | 只生效一次，返回同一结果 |
| 并发冲突 | 先成功者有效，后者拒绝并展示最新状态 |
| 跨入口操作 | 所有操作入口遵守相同规则，不能绕过名额、评价跨轮、结束及权限校验 |

## 5. 验收配套

下表使用合成数据与模拟角色。存在未决解释的分支按第 7 节保留，不能当作已可执行验收。

| 编号 | 场景与输入 | 可观察的预期结果 |
|---|---|---|
| A1 | 负责人初筛通过／不通过 | 通过产生 HR 邀约待办；不通过可结束；HR 后续操作不改写负责人评估 |
| A2 | 未约定明确时间即安排面试；暂未联系上 | 前者拒绝且不生效；后者由 HR 继续跟进，不自动结束 |
| A3 | HR 未登记完成时保存草稿、提交评价；登记完成后提交完整评价 | 可保存草稿，不能提交；完成登记后满足字段校验才可提交 |
| A4 | 已完成状态被取消或未到场操作覆盖 | 阻止覆盖；由 HR 核实更正并留痕，不静默覆盖原记录 |
| A5 | 同轮两名有效面试官，仅一人提交后尝试下一轮 | 拒绝正常下一轮；两人齐评后缺评限制解除，由负责人决定推进 |
| A6 | 部分评价已提交后调整安排 | 不允许修改整轮；取消未发生的个人安排可关闭对应任务；已发生未评者仍须补交；替换者独立评价 |
| A7 | 缺评时负责人作最终评估 | 可以决定，关闭未完成评价任务并保留历史；不伪装为已提交，不允许借此进入下一轮 |
| A8 | 原作者追加说明；他人修改原评价或署名 | 追加说明留时间，原结论保留；修改原评价、代改或改署名均拒绝 |
