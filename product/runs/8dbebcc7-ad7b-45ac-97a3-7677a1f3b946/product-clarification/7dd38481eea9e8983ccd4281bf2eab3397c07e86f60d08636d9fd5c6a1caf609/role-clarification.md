**三、需求主题及前三项依赖优先建议**

以下是依赖与返工风险排序，不能解释为缩减本期范围或已确定开发工期。材料不足以统计独立用户请求频次、量化收益或估算投入，不生成虚构评分。

| 主题 | 核心问题 | 对齐目标与依赖 |
|---|---|---|
| T1 招聘流程与责任闭环 | 不清楚当前由谁处理、何时可推进、如何结束 | 直接支撑协作；是待办、告警及验收的基础 |
| T2 业务对象与资料复用 | 同一候选人跨职位推进，资料共用但流程独立 | 决定查重、授权、简历绑定和历史保留 |
| T3 身份与权限隔离 | 配置权、业务处理权及正文访问权容易混淆 | 贯穿列表、详情、下载及全部写入动作 |
| T4 待办、告警与指标 | 遗漏处理、催办缺少统一依据 | 依赖真实状态、责任人、有效推进及时间记录 |
| T5 异常与数据治理 | 取消、更正、停用、并发及删除导致记录不一致 | 保证流程能安全收尾、证据不被覆盖 |
| T6 页面与字段一致性 | 前后端校验、失败反馈和筛选体验不一致 | 将业务规则转成可检查行为 |

前三项建议如下：

1. **先固化对象、主流程与提前结束规则。**  
   先区分候选人档案、应聘、轮次、场次和评价版本，再定义动作产生的状态与待办结果。否则多职位共用资料、串行多轮和终态清理容易互相影响。可用“正常三轮＋第一轮提前结束＋同轮取消重排”三组静态走查验证。仅记录阶段文字、依靠备注交接的替代做法不能满足本期责任与留痕要求。

2. **同步核对权限、共享资料及异常证据。**  
   重点验证共享资料更新不扩大跨职位权限、管理员不能默认读取正文、已交评价不能覆盖、完成时间更正不重启24小时、停用不遗失责任。可用同一候选人关联两个职位、不同HR与不同面试官的权限样例做最小核验。仅隐藏前端按钮不足以满足要求，服务端必须逐动作鉴权。

3. **基于上述结果映射工作台、字段与验收。**  
   待办、告警和指标应来自一致的业务记录，避免另建一套可人工修改的待办状态。先核对生成、转交、关闭、解除和统计口径，再展开页面及接口追踪。三类告警可并存，不能为了简化展示而互相覆盖。

以上建议的主要风险是下游漏传规则，而非仍缺关键业务选择；实际投入、性能和操作效率仍需后续实现与试点验证。

**四、对象关系与责任边界**

以下是业务关系，不限定数据库或接口实现。

| 对象 | 关系及规则 |
|---|---|
| 员工、账号、角色 | 员工与账号分离；每名员工最多1个有效账号，一个账号可兼任角色 |
| 职位 | 唯一主责HR、唯一负责人；二者必须有效且具对应角色，不能为同一账号；负责人可兼面试官 |
| 候选人档案 | 保存共享基础资料及简历版本；可关联多个职位的应聘 |
| 应聘 | 属于一个候选人和一个职位；保存独立流程、轮次、决定及简历绑定。同一候选人在同一职位最多1条非终态应聘 |
| 轮次 | 属于一条应聘，1—3轮串行；上一轮完成评价和负责人路由后才能追加下一轮，第3轮只能进入决策 |
| 场次 | 每轮一个有效面试场次，指派1—3名面试官；取消记录保留，同轮重排不增加轮次 |
| 评价及版本 | 对应场次及被指派面试官；草稿作者独见，提交后不可覆盖，符合条件时追加版本并保留旧版本 |
| 简历版本及绑定 | 私有PDF版本只增不覆盖；每条应聘显式绑定或替换版本，共享档案修改不自动替换应聘简历 |
| 待办、告警、审计 | 关联业务对象与责任人；待办以“对象＋动作＋责任人”唯一；审计保留执行事实并控制敏感信息 |

多职位同时推进不意味着共享流程或评价权限。再应聘、转岗均新建应聘；原流程需人工结束，终态不重开，不复制评价授权。

**五、状态转换与动作权限**

主线沿用：

`待HR筛选 → 待负责人初筛 → 待邀约 → 待面试 → 待决策 → 终态`

“待面试”期间还需表达排期、完成登记、评价收集和轮次路由进度。下游可设计辅助状态，但不得据此绕过串行轮次及决策门槛。

| 动作 | 执行人及前置条件 | 成功结果与拒绝边界 |
|---|---|---|
| 新建候选人、应聘 | 授权HR；关联职位可接收新应聘；通过手机号查重及字段校验 | 可先建档；手机号冲突拒绝，同职位已有非终态应聘时拒绝重复创建 |
| HR筛选推荐 | 主责HR；具有PDF及筛选摘要 | 转待负责人初筛并形成负责人待办；推荐前可由HR淘汰并留痕 |
| 负责人初筛 | 职位负责人亲自处理 | 通过后转待邀约；不通过留存决定；HR不能代录批准 |
| 登记邀约结果 | 主责HR | 成功才可排期；未联系上仍待邀约；拒绝转候选人退出 |
| 排期、改期 | 主责HR；邀约成功、符合串行轮次及人数限制、无冲突 | 更新场次与待办；冲突禁止；已完成或已有评价提交的场次不可直接改期 |
| 取消场次 | 主责HR；场次可取消，填写原因 | 保留取消记录；需要继续本轮时生成HR重排待办；不算追加轮次 |
| 登记实际结束 | 主责HR | 保留完成事实并生成面试官评价任务；未登记完成前不生成评价任务 |
| 提交评价 | 被指派面试官 | 提交通过／不通过／待议及文字依据；评价不自动淘汰候选人 |
| 追加评价版本 | 原作者；轮次尚未处理且应聘未终态；填写原因 | 追加版本保留原文；轮次处理后或终态只读 |
| 轮次路由 | 负责人；本轮评价齐备 | 第1—2轮可追加轮次或进入决策；第3轮只能进入决策 |
| 正常最终决定 | 负责人亲自处理，满足正常门槛 | 录用意向或不录用；录用意向不能借提前结束绕过门槛 |
| 提前结束 | HR记录有依据的候选人退出、职位终止；负责人可提前不录用 | 必填原因及实际执行人；无需等待评价齐备，统一执行终态清理 |
| 修改共享基础资料 | 同时具有档案访问权及至少一条关联职位主责HR身份 | 当前授权职位显示最新值；不扩散权限；手机号修改确认后重新查重 |
| 更正实际结束时间 | 仅主责HR；填写原因；轮次未处理且应聘非终态 | 保留旧值并重算告警，不重启24小时；误标完成仅追加说明，不回滚完成状态 |

提前结束必须同时满足：取消未发生场次、关闭未交评价任务、保留已完成事实及已交评价、终态不再生成或显示未完成待办。

职位及责任规则：

- 暂停后禁止新增应聘，既有流程继续，计时不停。
- 关闭前清理非终态应聘及未来场次，关闭后只读。
- 普通责任交接须新责任人接受后生效。
- 紧急停用立即撤销会话，相关责任转待分配，管理员24小时内分派；工作台显示异常，历史作者不改变。

访问控制沿用：

- 完整手机号仅主责HR可见；负责人、面试官查看脱敏值。
- 面试官仅访问被指派资料及本人评价，不看其他面试官评价。
- 无权访问的手机号匹配仅提示存在，不泄露候选人身份和所属职位。
- 管理员只维护人员、账号和角色，不自动取得候选人、简历或评价正文权限；兼任HR须显式授权并被指派。
- 简历使用不可猜UUID标识，列表、详情、下载和全部写入入口仍需服务端鉴权。
- 手机号变更审计加密或脱敏；审计不记录简历正文和完整手机号，管理员仅看操作摘要。

账号由管理员预建，采用用户名密码、服务端会话；默认会话8小时，退出或停用立即失效，连续5次失败锁定15分钟，密码安全散列。不提供自助注册和SSO。

**七、工作台、指标及失败反馈**

工作台由服务端查询、计算，按 `Asia/Shanghai` 自然小时处理，仅站内展示。

| 类型 | 触发口径 | 更新或解除 |
|---|---|---|
| 评价超时 | 实际结束24小时仍未提交 | 提交对应评价解除；终止关闭的任务不再作为应交 |
| 面试登记逾期 | 计划结束后仍未登记完成 | 完成登记或取消解除；改期按新计划结束重算 |
| 应聘停滞 | 非终态72小时无有效推进 | 有效推进重算；终态移除 |

有效推进白名单：建应聘、HR筛选推荐、负责人初筛、邀约结果、排期／改期／取消、完成登记、提交评价、轮次路由、最终决定／退出／终止。查看、普通备注、下载、资料修改、责任变更不重置计时。

待办覆盖HR筛选、邀约排期、取消重排、负责人初筛／轮次／决策、评价及关闭清理；已读不算完成。工作台默认本人未完成，逾期优先、截止时间升序。

指标采用工作台汇总卡：

- 评价按时率：以报告期实际结束场次应交面试官人数为分母；未满24小时列“未到期”，终止关闭任务剔除。
- 面试按时登记率：计划结束后24小时内完成登记的有效已发生场次／报告期已发生场次，取消剔除。
- 停滞占比：时点72小时未推进的非终态应聘／全部非终态应聘。
- 责任覆盖：有效非终态均应有有效主责HR及负责人，紧急待分配显示异常。
- 零分母显示“--”；先统计两周基线，再评价实际效果。

页面须覆盖空、加载、失败、无权限状态。职位筛选名称／状态／部门；候选人姓名／手机号查询受权限控制；应聘筛职位／阶段／主责HR／停滞。

查询失败保留筛选并可重试，提交中防重复；会话失效返回登录并保护未提交表单，不持久缓存敏感简历。服务端采用幂等及版本冲突控制：409返回当前版本，保留表单供核对，不自动覆盖。401表示未登录，403或隐藏404处理越权，400／409处理非法状态。失败不得改变业务或待办，上传失败不得留下悬空引用，不向用户暴露文件路径和异常堆栈。

| JS5 取消与重排 | 当尚未发生的面试无法按计划进行时，我希望说明原因并在同轮重排，以便保留过程且不误耗轮次 | 取消必填原因；旧场次保留；生成HR重排待办；不增加轮次；已完成或已有评价提交时禁止直接取消、改期 |

跨故事补充边界验收：

- 岗位名测试0、1、100、101字符；姓名测试50、51字符；原因、摘要、评价依据分别覆盖上限及超限。使用“张三”“𠮷”和组合字符样例核对前后端计数一致性。
- PDF覆盖0字节、10×1024×1024字节、边界加1字节；失败后不存在可下载的悬空资料引用。
- 无权账号直接请求详情、完整手机号、评价及PDF下载，应被拒绝且无正文泄露。
- 两名有权用户同时编辑同一记录，后提交者遇版本冲突时保留表单，不覆盖前者结果，不误更新待办。
- 评价24小时、停滞72小时、删除180自然日均覆盖阈值前、阈值点和阈值后；完成时间更正同时验证告警重算和原24小时期限保留。

**九、交接核验、待决项与下一角色输入**

本次按交接方法核对了依据、范围、动作前置条件、权限、成功结果、拒绝条件及失败数据影响。关键规则可同时成立：

- 正常录用意向受完整门槛约束；提前退出、职位终止和不录用走明确的收尾规则。
- 场次完成事实保留；有限时间更正和评价追加版本不覆盖历史证据。
- 基础资料共享；应聘流程、简历绑定及评价访问继续隔离。
- 紧急停用允许短期待分配，同时显示责任异常，不把异常计作正常覆盖。

**目前没有阻止产品成稿的未决业务选择。** 布局等可选偏好不阻塞；提前删除政策例外尚未批准，本期不启用。真实数据隐私确认是启用门禁，不阻止合成数据设计与验收。若后续发现原始资料存在真实冲突，应列明受影响规则和阻塞行为，其余有效规则继续保留。

交给产品闭环角色：核对正常、提前结束、取消、更正、跨职位权限、并发、停用及删除场景，重点检查待办和告警生成、更新、解除的一致性。

交给产品写作角色：据本稿与闭环结果汇总项目总览、平台与人员权限PRD、招聘PRD、工作台PRD、字段状态附录、需求—页面—接口—验收追踪表及用例。正式包需覆盖登录导航、各类列表详情、应聘详情、排期评价、决策、人员账号管理及按钮前置条件；讨论及受托决策记录单独组织。
